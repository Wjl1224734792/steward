# 项目全生命周期规范（project-lifecycle）

**一句话**：把每次改动都当成一次可审计的交付——先弄清现状，再约定结果，小步改，用证据收尾，把知识留在仓库里。

**最小闭环**：读指令 → 看状态 → 跑基线 → 定 AC → 最小改 → 复跑 → 落档 → 交接。跳过任何一步都要说明理由。

本技能只使用 Agent Skills 标准字段（`name` / `description`），不依赖宿主专有工具、模型、脚本或子代理；支持 `SKILL.md` 的代理都能加载。

## 0. 适用与优先级

- 适用：任何软件项目的开发、维护与长期演进；单个代理顺序执行即可。
- 不适用：纯问答、一次性脚本、只读咨询——可只取第 7 节的完成定义。
- 优先级：**宿主/仓库指令**（`AGENTS.md`、`CLAUDE.md`、`README`、`CONTRIBUTING`、`docs/`）> 本规范 > 个人偏好。
- 若存在更具体的技能（TDD、系统化调试、发布流程、文档流水线），其对应小节优先；本规范负责把它们串成完整闭环。
- 子代理不是前提：没有子代理就串行完成全部阶段；即使宿主能派子代理，门禁、证据与责任仍由当前代理承担。

## 1. 三条底线

1. **仓库是事实来源。** 先读后写；以代码、测试、配置、提交历史和仓库指令为准，不凭记忆或猜测修改。
2. **证据才算完成。** 在最后一次改动**之后**复跑门禁，报告命令、退出码和真实输出；"应该能过"等于没做。
3. **小步、可逆、可回滚。** 一次只解决一个关注点；不可逆或高风险操作先说明影响并取得明确同意；不 force-push 共享分支，不删数据，不关闭测试/鉴权/审计来"让流程通过"。

## 2. 工作环（七步）

| # | 步骤 | 关键动作 | 产出 |
|---|---|---|---|
| 1 | 受理 Intake | 判定模式；确认目标、AC、非目标、风险 | 任务卡（S 级可三行口述） |
| 2 | 勘察 Recon | 读指令与 README；看 git 状态/历史；定位命令；跑基线 | 现状摘要 + 基线结果 |
| 3 | 立约 Contract | 固定改动边界、验收方式、回滚方案 | 可执行的计划 |
| 4 | 实施 Implement | 最小 diff；行为变更先测；重构先补特征测试 | 代码 + 测试 |
| 5 | 验证 Verify | 目标测试 → 全量相关门禁 → AC 逐条取证 → diff 自审 | 证据清单 |
| 6 | 落档 Record | 按活 / 记录 / 基线三类落档：changelog / 文档 / ADR / 状态文件 | 仓库内的知识 |
| 7 | 交接 Handoff | 状态、证据、风险、下一步 | 自包含的交接块 |

每一步的产出都要能被下一个人（或下一轮会话）直接看到，而不是只存在于当前对话。

## 3. 模式路由

| 模式 | 触发 | 必做 | 出口条件 |
|---|---|---|---|
| 接手 Adopt | 存量仓库、缺少上下文 | 勘察 + 基线 + 风险清单 + 渐进计划 | 能构建/测试；简报与状态建立 |
| 新建 Greenfield | 从零开始 | 简报 + walking skeleton + 垂直切片 | 首个可用版本 + 运行说明 |
| 功能 Feature | 新增或修改行为 | 任务卡 + 测试 + 文档 | AC 全绿 + 证据 |
| 缺陷 Bug | 行为不符合预期 | 复现 + 根因 + 回归测试 | 红→绿证据 + 原因说明 |
| 维护 Maintenance | 周期健康、依赖、债务 | 扫描 + 分级 + 小批修复 | 维护报告 + 债务登记 |
| 演进 Evolution | 重构、迁移、弃用 | 特征测试 + expand-contract + 回滚 | 旧路径删除 + 决策记录 |
| 发布 Release | 对外交付 | 版本 + changelog + 迁移说明 + 演练 | 可回滚的发布 + 发布后验证 |

模式可嵌套：大演进中的每个切片按 Feature 走；发布前的修复按 Bug 走。分步流程见 [development.md](references/development.md) 与 [maintenance.md](references/maintenance.md)。

## 4. 立约：任务卡

非 S 任务开始前，用六行回答（模板 [task-brief.md](assets/task-brief.md)）：

1. **问题与影响**：谁受到影响，现状为什么不行。
2. **验收标准（AC）**：可观察、可判定，逐条编号。
3. **非目标**：这次明确不做什么。
4. **边界与约束**：文件、接口、数据、兼容性、依赖。
5. **风险与回滚**：最坏情况、触发条件、恢复步骤。
6. **验证计划**：要跑的命令、要看的证据。

规则：

- AC 必须可观察：测试、日志、截图、可复现步骤；"更优雅""更清晰"不是 AC。
- 超过 1 天或触及公共接口 → 拆成能独立验证的切片，每片有自己的 AC。
- 需求含糊但可逆 → 选最小合理解释，把假设写进任务卡；不可逆或影响产品方向 → 停下来问。
- 需求不清时最多问 3 个**会改变范围**的问题；其余用可逆默认。先给一个最小可交付解释让用户纠正，不用问题清单拖延。
- M/L 任务先把任务卡与计划写出来（可同步给用户，不必等待批准）；S 任务可直接做（用户已明确授权时）。
- 不做沉默的范围扩张：发现额外问题记入"发现"清单，另行处理。

## 5. 勘察清单

- **指令**：`AGENTS.md` / `CLAUDE.md` / `CONTRIBUTING` / `README` / `docs/` 中的约定、命令与禁区。
- **状态**：`git status`、当前分支、最近 10 条提交、未提交改动；绝不覆盖他人的工作。
- **未提交改动**：先确认归属；不 stash、不 checkout、不覆盖。不是自己的改动就绕开或先问，必要时只读分析。
- **结构**：入口、模块边界、依赖清单、配置与环境变量、数据模型与迁移、部署方式。
- **命令**：安装、构建、测试、lint、类型检查、本地运行；确认 CI 用的是哪一套。
- **基线**：先跑最快的相关门禁并记录已有失败；不把既有失败算到自己头上，也不趁机修无关问题。
- **边界**：密钥、生产数据、危险脚本、部署入口；默认只读，写操作先确认影响面。

## 6. 实施纪律

- **最小 diff**：沿用现有风格与抽象层级；不顺手格式化、不改无关文件、不做"顺便重构"。
- **测试先行**：行为可测时先写失败测试（确认因预期原因失败），再写最小实现；不可自动化时写下手工验证步骤。
- **缺陷**：先稳定复现并定位根因；没有失败测试不修；不可测时用日志/断言/监控做守卫。
- **重构**：先补 characterization 测试，重构不改变行为；重构与功能改动分开提交。
- **破坏性变更**：走 expand-contract（新增 → 双写/双读过渡 → 迁移 → 删除旧路径），提供迁移说明与回滚。
- **数据/架构迁移**：先备份或快照，支持 dry-run，向前与回滚都验证；不可逆迁移单独评审。
- **依赖**：优先标准库与既有依赖；新增依赖要说明理由、许可证、体积、维护状态和安全记录；遵循仓库的锁文件与版本策略。
- **生成物**：构建产物、快照、代码生成文件不手改；改源头并重新生成；锁文件用包管理器更新，不手编。
- **安全**：不硬编码密钥、不记录敏感信息、边界校验输入、服务端鉴权、最小权限；不关闭 TLS/鉴权/审计来"让测试过"。
- **Git**：小提交、语义清晰的 message；不 amend/force-push 别人的提交；不提交生成物、密钥或临时文件。

## 7. 验证与完成定义

完成 = 以下全部成立（细节与证据格式见 [verification.md](references/verification.md)）：

1. **AC 逐条有证据**：每条 AC 对应测试、日志、截图或可复现步骤。
2. **复跑门禁**：最后一次改动后运行 build / typecheck / lint / test（按仓库实际）；报告命令、退出码、关键输出。
3. **测试诚信**：相关测试全绿；flaky 用重复运行确认并记录；新增/修改测试有红→绿过程或不可测说明。
4. **diff 自审**：无调试残留、无密钥、无越界文件、无被注释掉的代码、无意外生成物。
5. **文档按类治理**：行为、接口、配置、运维方式变化时按「活 / 记录 / 基线」三类落档（活文档原地改、记录只增不改、基线版本 bump），版本 / 修订表 / 索引三处一致；"以后补文档"视为未完成。
6. **文档门禁**：仓库有文档门禁脚本就跑并贴输出；没有则逐项过 [documentation.md §8](references/documentation.md) 的自检清单。
7. **风险可控**：风险改动有回滚步骤；未验证项逐条列出。

**证据格式**（按需裁剪）：

```text
命令：<完整命令>（工作目录：<路径>）
结果：exit 0
关键输出：<2–5 行>
时间：<YYYY-MM-DD HH:mm>  环境：<本地/CI/版本>
```

**禁止**：用上次输出、推断或他人转述代替复跑；跳过/删除/弱化测试；只跑目标测试就宣称全绿；把失败解释成"已知问题"继续交付。

**无法验证时**：明确写"未验证 + 原因 + 建议的验证方式"，不降低完成标准。

**收尾六问**：① 最后一次改动后复跑了吗？② 每条 AC 都有证据吗？③ diff 只含本任务且干净吗？④ 文档按三类落档、版本与索引一致吗？⑤ 文档治理自检（体积 / 索引 / 快照 / 依据）过了吗？⑥ 接手者能不看对话继续吗？

## 8. 长期维护（心跳）

维护不是"有空再说"，而是固定节奏的小步循环：

| 周期 | 动作 | 产出 |
|---|---|---|
| 持续 | CI 绿、告警有人处理、依赖更新不积压、错误日志有入口 | 稳定的主干 |
| 每周 | CI/告警健康、flaky 测试、补丁与次要依赖、债务 Top 3 | 周报或看板更新 |
| 每月 | 依赖审计与 EOL、死代码与重复、文档漂移、备份可恢复性、性能基线、权限复核 | 月度维护报告 |
| 每季度 | 路线图复盘、重大升级/迁移、架构适配度、弃用执行、灾难恢复演练、测试套件健康 | 季度评审 + 下季计划 |
| 每半年 | 许可证/合规、威胁模型、平台 EOL、成本复核 | 风险登记更新 |

- 债务必须有登记：**现象 / 影响 / 触发条件 / 负责人 / 下一步 / 到期日**。不登记就等于不存在；到期要么修，要么明确接受并记录理由。
- **文档漂移 = 缺陷**：README 命令跑不通、注释与行为不符、架构图过期，按缺陷修复。
- 每次维护产出一页报告（模板 [maintenance-report.md](assets/maintenance-report.md)）：健康度、风险、已做、计划、债务变化。
- 完整扫描项与分级方法见 [maintenance.md](references/maintenance.md)。

## 9. 演进与弃用

- **先定义为什么演进**：用户价值、成本、风险；没有可度量目标不做大重构。
- **绞杀者模式**：新路径并行存在，调用方逐步迁移，旧路径保留一个弃用窗口后删除。
- **弃用政策**：公告 → 警告（带替代方案与日期）→ 删除；默认至少跨 2 个次版本或 90 天（取较晚者），以仓库政策为准。
- **契约意识**：公共 API、事件、数据库 schema、配置项都是契约；变更要版本化、有迁移指南和回滚方案。
- **kill criteria**：功能与项目立项时写下"什么条件下停止"；到期不达标就下线或归档，不做僵尸功能。
- **删除也是交付**：删旧代码、旧开关、旧文档、旧依赖，并在 changelog 记录。

## 10. 项目记忆与文档治理

- **先发现，后创建**：仓库已有 `docs/`、ADR、`CHANGELOG`、issue 模板就沿用，不另起一套。
- **最小常青集（按需）**：项目简报、决策记录（ADR）、变更日志、当前状态/交接。
- **持久事实进团队文档**（提交入库）；临时工作状态可放 `.agents/state/current.md`（可 gitignore）；重要决策不能只存在于临时状态。
- **三类文档三种待遇**：**活文档**（指令文件、README、架构、契约、设计）原地修订，靠体积预算 + hub-and-spoke 拆册控制长度；**记录文档**（ADR 单条、评审记录、复盘、changelog 条目）只增不改，靠薄索引 + 归档轮转；**基线文档**（需求规格、数据模型、有冻结语义的契约）原地修订 + 里程碑快照。判不准就按更严一类处理。
- **体积预算**：入口文件与单册都要设行数上限（默认值见 [documentation.md §2](references/documentation.md)）；超限就拆册；存量项目先记基线，之后只减不增。
- **现版路径稳定，基线冻结才快照**：版本号永不写进文件名；快照进 `history/` 并记哈希，头部标"已被新版取代"；条目编号永不复用、永不重排。
- **读契约分级**：恒读只给短小的入口与红线；条件必读靠目录 / 任务点名；其余按需检索。读长文先索引、再定位、后片段读，禁止整文件倾倒；实现任务不读历史区。
- **ADR 门槛**：难以回滚、跨模块/跨团队、成本超过 1 天、限制未来选项——满足任一即记录（模板 [decision-record.md](assets/decision-record.md)）。
- **同一改动更新文档**；"以后补文档"视为未完成。
- **单一事实来源**：能链接就不复制；必须复制时标注同步来源。
- 记忆载体、决策与上下文管理见 [memory.md](references/memory.md)；分类 / 预算 / 拆册 / 读契约 / 版本快照 / 自检清单见 [documentation.md](references/documentation.md)。

## 11. 上下文与交接

- 长任务每完成一个里程碑就把状态写盘：目标、已完成、证据、未决问题、下一步、关键路径。
- 恢复会话先读状态 + `git status/log` + 复跑最快门禁，再继续；不要凭记忆续写。
- 上下文将满时优先保留：决策与理由、文件路径、命令、验证结果、未完成项；丢弃寒暄与重复输出。
- 交接必须自包含：接手者不看历史对话也能继续（模板 [handoff.md](assets/handoff.md)）。
- 有子代理也不改变门禁与证据标准；使用子代理时，其结论仍需自己复核。

## 12. 能力降级（任何 harness 都能用）

| 缺少的能力 | 替代做法 | 不得 |
|---|---|---|
| Shell / 命令执行 | 用文件工具编辑；把命令与预期输出写进交接，请用户执行 | 假装命令已运行 |
| 测试框架 | 最小冒烟脚本或手工清单，记录步骤与结果 | 宣称"测试通过" |
| Git | 改动前带时间戳备份，手工生成 diff | 覆盖无法恢复的文件 |
| 网络 | 标注"外部事实未核实"；优先仓库锁文件与本地文档 | 编造版本号或 API 行为 |
| 子代理 | 串行执行全部阶段 | 伪造并行或委派 |
| 持久化 | 结束时输出完整交接块 | 把关键决策留在对话里 |
| 只读权限 | 产出计划、补丁建议与验证步骤 | 声称已修改或已验证 |
| 文档门禁脚本 | 按 [documentation.md §8](references/documentation.md) 的清单人工逐项核对 | 跳过核对就宣称"文档没问题" |
| frontmatter / 元数据 | 用文档头部一张表等价承载 read / version / status | 假装元数据存在 |

## 13. 沟通

- **默认不请示**常规、可逆的工作；只在以下情况停下来问：产品方向/范围取舍、不可逆或高风险操作、需要凭据或付费资源、仓库指令冲突、安全/合规判断。
- **进度更新四段式**：做了什么 / 证据 / 风险与决策 / 下一步。
- **失败要具体**：哪条命令、什么错误、已排除什么、下一步试什么；不用"环境问题"含糊带过。
- **三次原则**：同一问题连续 3 次尝试没有实质进展，停下来汇报，附已尝试方案、当前假设与需要的帮助；不无限试错。
- **不夸大**：没跑的别说跑了；部分完成就说部分完成。
- **最终汇报**先给结果，再给证据，最后给文件位置与未决事项。

## 14. 反模式（出现即违规）

- 没读仓库就改；凭记忆编 API、版本或配置。
- 完成声明没有复跑证据；用"应该""之前跑过""别人说"。
- 为变绿删测试、跳过测试、弱化断言、盲目更新快照。
- 大而全重写、顺手重构、沉默的范围扩张。
- 把失败归为"已知问题"继续交付。
- 引入无理由依赖；升级不做回归。
- 破坏性操作没有回滚；force-push 共享分支。
- 文档/CHANGELOG 不更新；临时状态成为唯一事实来源。
- 把"我改完了"当成交付，不写验证方式与剩余风险。
- 三类文档用一套规则：活文档越写越长没人拆，记录文档原地反复改。
- 把版本号写进文件名（`XX-v2.md`）、按时间拆册——造出多份"现版"互相打架。
- 手改历史快照，或把历史区当现行口径（实现按旧基线漂移）。
- 把所有评审都往长期文档里倒（run 级报告应留在工件目录）。
- 归档 / 拆册后不更新索引，链接和索引指向旧位置。
- 修订行不挂依据，条目编号重排或复用——变更无法溯源。

## 15. 快速开始（任何仓库的前 30 分钟）

1. 读 `AGENTS.md` / `README` / `CONTRIBUTING`，记下命令与禁区。
2. `git status` + `git log -10` + 当前分支；确认没有别人的未提交改动。
3. 画 5 行地图：入口、核心模块、数据、外部依赖、部署方式。
4. 跑最快门禁，记录基线（含已有失败）。
5. 写任务卡（模式 / AC / 非目标 / 风险 / 验证），选最小切片开工。
6. 每完成一片：验证 → 落档 → 汇报；循环。
7. 结束：更新状态与 changelog，给出交接块。
