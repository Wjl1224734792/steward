# 联动规则与维护细则（改 A 必同改 B）

> 路径基准：业务文档在 `docs/`，约束与规范条款在根/子目录 `AGENTS.md`，规范正文在 `.agents/rules/`，工作流细则在 `.agents/skills/`，视觉在 `.agents/designs/`。

## 一、联动表（同一批变更 完成）

| 改动类型 | 必须同改 | 验证方式 |
|---|---|---|
| 接口路由 / schema / 错误码 | `docs/03-契约/` API 文档 | manifest（openapi 等）paths 数对比 |
| 专项接口（MCP Tool / RPC / 事件） | `docs/03-契约/` 或 `04-专项/` 清单；权限边界变化同改安全架构文档 | 清单数 ↔ 实装数核对 |
| 表 / 字段 / 键 / 存储 | `docs/03-契约/` 数据模型 + 全部含实体清单的文档 + 迁移脚本 | 迁移可执行；多处实体数一致 |
| 领域参数（费率/上限/阈值/生效日期） | 参数 SSOT 清单 + 需求文档相关节 + `docs/06-测试/` 黄金集期望值 | 黄金集期望重算；算术口径复核 |
| 业务流程 / 规则闸口 | `docs/01-需求/` 流程文档 + 覆盖对照表 | 无孤儿闸口 |
| 页面 IA / 路由 / 布局 / 组件 / 详设 | `docs/05-页面/`（页面设计路由表 + 布局稿 + 详设分册对应页与组件清单） | 路由数 ↔ 布局矩阵行数 ↔ 详设页数一致（无孤儿路由）；每页布局可判定 |
| 页面布局 / 栅格 / 断点 / 滚动与吸底归属 | `docs/05-页面/` 布局稿（或详设 §3）+ 对应详设 + 前端实现 + 浏览器实看证据；动壳/滚动同改 DESIGN.md 布局框架节 | 每页区域/断点/四态可判定；唯一滚动容器；截图或实看证据 |
| 页面视觉（色值/token/主题） | `.agents/designs/`（DESIGN.md 或主题参考；稿与代码同源） | 视觉走查 |
| 日志字段 / 关联 ID（trace）头与贯穿链 / 告警三要素 | 可观测性工程化文档 + API 契约（若关联 ID 是契约字段）+ 对应层级规范条款（+ 审计/事件表列若作关联键） | 日志样例对照字段字典；告警有接收人与动作 |
| 技术选型（模型/库/队列/协议/鉴权） | **先**新建 `docs/07-治理/ADR-000X` 再改代码 | ADR 状态：提议→接受→已落地 |
| 完成代码功能或修复 | `docs/07-治理/执行步骤.md`（现状盘点 + 剩余工序） | — |
| 开发顺序：波次顺序/模块归属/估算/依赖变更 | `docs/07-治理/开发顺序.md` 重排 + `执行步骤.md` 销项状态（同一批变更 留痕） | 两文档波次与状态一致 |
| 新需求/新功能/口径变更进入项目 | 先走 README §5.4 变更入口（影响面扫描 → 用户拍板 → 留痕），再按本表逐行联动落档 | 拍板留痕（ADR/评审记录/PRD 修订记录三者之一） |
| PRD 的 FR 新增 / 改口径 / 改批次 | FRD 对应 FP（展开或调整）+ FR↔FP 追溯表；波及契约/页面/黄金集的按其余各行联动 | FR↔FP 双向无孤儿；AC 与 GT 有落点 |
| FRD 功能点变更（字段/规则/状态/异常/权限） | PRD 追溯与 AC 核对 + 契约文档（数据模型/API/错误码）+ 黄金集 + 页面详设对应页 | 契约字段与 FP 字段一致；黄金集期望重算 |
| 新建/删除/重命名文档 | `docs/README.md` 索引 + 根 `AGENTS.md` 文档索引 + 各文档互引 | 路径可打开；全局搜旧名零残留 |
| 新建/删除/重命名代码产物（源码 / 测试 / 迁移目录 / 种子 / 脚本） | 命名规范（编码 What，禁阶段/工单编号）+ 存量基线同步删对应行 | 命名守卫绿灯；基线只减不增；已应用迁移目录不改名 |
| 新增/删除模块、包、目录 | 对应层级 `AGENTS.md` 增删 + 根 AGENTS §目录结构 | 层级 AGENTS 与实际目录一致 |
| 启动命令 / 环境要求 / 端口 / 依赖变化 | 根 `AGENTS.md` §命令速查 + `README.md` | 命令真实可跑 |
| 工具链 / 工作流 / Agent 行为变化 | 根 `AGENTS.md` §工作流 | — |
| 新增/改「必须遵守」约定 | 优先写成本地门禁/lint 脚本；红线条目（≤1 行）摘进对应 AGENTS 层 | 脚本对反例能红灯 |
| 编码规范条款新增/修改 | 对应层级 `AGENTS.md` 规范条款 或 `.agents/rules/` 对应文件 + 核对两侧摘录与必读引导一致 | rule frontmatter globs 与实际目录一致 |
| mermaid 图改动 | 该文档本身 | 真实渲染：围栏内无裸文本/无 `=` |

**执行口诀**：改契约 = 改文档 + 改代码 + 改自查，三件事一批变更。

## 二、文档维护规范（全周期）

> 原则：代码即文档，文档即代码——每次改动必须同步维护受影响文档。

```
□ 新增/删除文件、模块 → 对应层级 AGENTS.md 架构概览仍准确
□ 新增/修改命令 → AGENTS 命令速查 + README 开发命令仍正确
□ 新增/修改 FR 或功能点 → PRD 与 FRD 追溯表已同步（FR↔FP 无孤儿）
□ 新增/修改 API → docs/03-契约/ 已更新
□ 新增/修改配置 → docs/ 对应文档已更新
□ 日志 / trace 头 / 告警口径改动 → 可观测性工程化文档已更新（+ 契约字段 + 层级规范）
□ 改动影响架构决策 → ADR 已写
□ 版本 bump → 文档头部状态行 + docs/README.md 状态列 + 执行步骤盘点
```

## 三、冲突处理与可靠性排序

```
本地门禁拦截 > pre-commit hook > lint/tsc > 根 AGENTS.md 红线 > 子目录 AGENTS.md > .agents/rules/ 规范 > README 正文 > docs/README 散文
```

- 文档与代码不一致：**以代码为准回填文档**（安全红线/领域硬口径被破坏除外——停下讨论）。
- 需拍板分歧（选型/归属/口径/金额）：列进评审记录等用户拍板，**AI 不私改**。
- 红线增删只改所在层 AGENTS 一处（单权威，全产品生效）。

## 四、存量文档迁移 SOP（需用户拍板后执行）

```
1. 出映射表（现路径 → docs/01~07 目标路径）给用户确认
2. 建 docs/01-需求 ~ 07-治理 子目录
3. git mv 移动（保留历史；无 git 仓库先 init 或移动后补记录）
4. 建/更新 docs/README.md 索引 + 根 AGENTS 文档索引
5. 更新文档互引路径（「资料来源」清单等）
6. 全局替换旧路径引用（含 .agents/rules/、.agents/skills/ 内的引用）
7. 检查本地门禁/docs-guard 脚本硬编码路径（若有）
```

## 五、临时文件规范

- 一切临时脚本/实验代码/调试输出进 `tmp/`（可按日期或用途分子目录），`tmp/` 进 `.gitignore`。
- 禁止散落在仓库根、桌面；功能验证通过后及时清理。
- 构建产物/缓存目录（`node_modules/`、`dist/` 等）按各自构建系统约定，不属本条范围。
