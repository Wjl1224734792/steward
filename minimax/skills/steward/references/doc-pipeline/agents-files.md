# AGENTS 层级体系（渐进式披露与引导）

> `AGENTS.md` 是跨 AI 产品的通用约束入口（开放约定，不绑定任何 harness）。本文件管：分层模型、根/子目录骨架、生成时机、写作规范、维护规则、多产品共存。

## 1. 渐进式披露模型（每层只写自己的事）

```
AI 每轮自动加载 ──▶ 根 AGENTS.md          （红线 + 全局规范条款 + 索引 + 工作流，≤100 行）
进入模块目录时 ───▶ 子目录 AGENTS.md       （该模块局部规则 + 本层规范条款，≤100 行/份）
改该层代码前 ────▶ .agents/rules/*.md     （规范正文：全局 + 层级，AGENTS 引导必读）
任务触发时 ──────▶ .agents/skills/*/README.md（工作流技能，按需加载，不限长）
要改内容时 ──────▶ docs/（业务 SSOT）      （需求/架构/契约/测试/治理）
机器每次提交 ────▶ 本地门禁/lint（L1 门禁）      （能机检的不靠文档）
```

**引用不复制**：下层不复制上层红线；AGENTS 不复制 skill/docs 正文，只留 ≤1 行 + 指针。判断内容放哪层的决策树：

```
新约束 → 能写成 lint/本地门禁？ → 是：沉 L1 门禁 + AGENTS 一句话
                         → 否：违反后果严重（安全/数据/阻塞协作）？
                                → 是：AGENTS 红线（全局进根，局部进子目录）
                                → 否：属「怎么写代码」的约束性条款？
                                       → 是：写进对应层级 AGENTS 规范条款；
                                              正文过长拆 .agents/rules/ + AGENTS 必读引导
                                       → 否：流程/工艺指南 → skill 正文；业务口径 → docs
→ 新建了文件 → 同步根 AGENTS 文档索引 + docs/README.md（rules 新增同步对应 AGENTS 层必读引导）
```

## 2. 根 AGENTS.md 骨架（复制填空）

```markdown
# AGENTS.md — 本项目唯一执行入口（人 + AI 都认它）

> 红线与全局规范条款权威在本文件；模块局部规则与本层规范条款在各子目录 AGENTS.md；
> 规范正文在 .agents/rules/（改代码前必读，本文件索引引导）；工作流技能在 .agents/skills/；
> 业务规范在 docs/。偏离就停下说明，不猜。

## 1. 约束分层
| 层 | 位置 | 写什么 |
|---|---|---|
| L1 门禁 | 本地门禁 / lint | 能机器拦截的检查 |
| L2 红线与规范 | 本文件 + 子目录 AGENTS.md | 禁止/必须 + 规范条款 + 索引 + 工作流 |
| L3 规范正文与细则 | .agents/rules/（规范正文，AGENTS 引导必读）+ .agents/skills/（工作流技能） | 编码规范展开与工作流指南 |
| L4 业务 | docs/ | 需求/架构/契约/测试/治理 |
冲突优先级：本地门禁红灯 > 可选 pre-commit hook > lint/tsc > 根 AGENTS 红线 > 子目录 AGENTS > .agents/rules > 本库 > docs 散文。

## 2. 文档索引（改什么先读什么）
| 改什么 | 先读什么 |
|---|---|
| 需求/验收口径 | docs/01-需求/<PRD>.md + <FRD>.md |
| 架构/分层/选型 | docs/02-架构/架构设计.md + {X}工程化.md |
| 接口/错误码 | docs/03-契约/<API文档>.md |
| 表/字段/存储 | docs/03-契约/<数据模型>.md |
| 测试/门禁 | docs/06-测试/<测试方案>.md |
| 编码细则/TDD | 本文件 §红线 + .agents/rules/coding-standards.md（全局）与 .agents/rules/<对应层级>.md |
| 进度/决策 | docs/07-治理/执行步骤.md + ADR |

## 3. AI 工作流（强制）
1. 打开上表对应规范再动手，不凭记忆写；改代码前必读本文件/子目录 AGENTS 规范条款 + .agents/rules/（全局 + 本层）；任务先查 .agents/skills/ 有无匹配技能。
2. 回复开头声明一行：`对齐文档：<文件> §<节> + Rules/Skill §<节>`。
3. 核心功能 TDD：先写测试再实现；新文件写文件头注释（职责+链路+对齐章节）。
4. 改接口同步契约；改表同步数据模型；改页面同步页面设计与 designs/。
5. 贴验证命令真实输出，不说「应该过了」。

## 4. 红线（每条 ≤1 行，带细则指针）
- 禁止 <具体行为>（细则：docs/… §x）
- 必须 <具体行为>（细则：.agents/rules/<文件> §y 或 skill <name> §y）

## 5. 目录结构
（架构定稿后填实际目录树，一行一注释）

## 6. 命令速查
# 门禁链（按项目实际工具填）
<lint> && <typecheck> && <test> && <build>
```

## 3. 子目录 AGENTS.md 骨架（模块级，进入该目录时加载）

```markdown

## 局部目录与分层
<目录树 + 每层职责 + 依赖方向（如 endpoints 薄 / services 厚 / 禁反向依赖）>

## 局部红线与规范（≤5 条，只写本层新增）

## 对齐文档
docs/02-架构/{X}工程化.md ｜ docs/03-契约/…

```

## 4. 生成时机（该写入时就写入，不提前不滞后）

| 文件 | 时机 |
|---|---|
| 根 `AGENTS.md` 占位 | 从零项目骨架期（红线/索引可先空着，边写边填） |
| 根 `AGENTS.md` 补全 | **架构阶段目录结构定稿后**（§5 目录结构、§6 命令速查、红线具体化） |
| 子目录 `AGENTS.md` | **创建对应模块目录时**；新增模块同步新增；删除模块同步删除 |
| 接手项目 | 盘点完成后一次性生成根 + 各现存模块（红线从现行代码提炼实际生效的约定，不凭空发明） |

## 5. 写作规范

- 红线每条 ≤1 行，带禁止/必须/绝不，末尾指向细则（docs §x / skill §y）。
- 根文件整体 ≤100 行；超了就把正文拆进 .agents/rules/（规范类）或 skill（工作流类）或 docs（业务类），AGENTS 只留指针。
- 收录门槛：安全/数据事故、阻塞协作、或本地门禁已拦但需提前告知 → 进 AGENTS；其余进 skill/docs。
- 索引表一行一文档，不堆历史版本（历史进 `docs/07-治理/执行步骤.md`）。
- 不写教程式长文；解释放 skill。

## 6. 维护规则（与代码同一批变更）

| 变更 | 同步动作 |
|---|---|
| 工具链 / 工作流 / Agent 行为变化 | 根 AGENTS §3 工作流、§6 命令速查 |
| 新增/删除模块、包、目录 | 对应层级 AGENTS.md 增删 + 根 §5 目录结构 |
| 启动命令 / 环境要求 / 端口 / 依赖变化 | 根 AGENTS §6 + README |
| 红线增删 | 只改所在层一处（单权威的最大收益：一处改、全产品生效） |
| 红线有对应机检能力了 | 沉到本地门禁/lint，AGENTS 该行改为一句话提醒 |
| 版本 bump | 索引路径复核 + docs/README.md 状态列 |

**发布前 checklist**：
- [ ] 每条红线 ≤1 行且有细则指针
- [ ] 无长正文（解释在 skill/docs）
- [ ] 子目录 AGENTS 无根红线复制
- [ ] 索引表路径全部可打开
- [ ] 命令速查真实可跑

## 7. 多 harness 共存（不绑定任何产品）

1. **根文件只写一份**：通用 `AGENTS.md` 为唯一红线权威；换 AI 产品不搬家。
2. 某产品不自动读根 `AGENTS.md` → 用**该产品自己的配置**（人负责）指向根文件，或放一行「权威见根 AGENTS.md」薄引用。
3. **禁止**在产品目录（`.zcode/`、`.claude/`、`.cursor/`、`.mimocode/` 等）另立正文；**禁止**「多副本 + 脚本同步」模式——副本漂移无机器拦截时必然腐化。
4. 规范正文一份在 `.agents/rules/`、技能正文一份在 `.agents/skills/`；某产品需本地安装位（其自有 rules/skills 目录）时由人设薄指向或按需复制，不设自动同步。
5. 本地门禁只配一份，不随 harness 变。
