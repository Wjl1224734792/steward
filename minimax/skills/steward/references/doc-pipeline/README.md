## 核心原则

1. **产物先于实现**：先文档后代码，先冻结契约再联调。
2. **单一事实源 SSOT**：每主题一份权威，其他**引用不复制**（写「见 docs/xxx.md §Y」）。
3. **联动同改**：改 A 必同一批变更改 B（§4；全表 `sync-rules.md`）。
4. **门禁先于阶段**：阶段产物过独立评审才进下一阶段（§6.4）。
5. **变更先拍板**：新需求/口径/范围先过 §5.4 变更入口（影响面 → 拍板 → 落档），AI 不私改。
6. **可验收**：每 FR 有可量化 AC，不写「体验好」「功能正常」。
7. **能进门禁的不写进文档**：规范优先落本地门禁/lint，文档只作补充。
8. **渐进披露**：根 AGENTS（每轮，短）→ 子目录 AGENTS（进目录）→ rules（改码前必读）→ skill（触发才加载）→ docs（要改才读）。
9. **实践回填**：项目验证有效的新产物/新口径（开发顺序、三表执行步骤、数据访问规范……）回填本库模板——本库随项目进化，不是一次定稿。

### 0.4 AGENTS 层级与生成时机

根 `AGENTS.md`：从零项目骨架期占位、**架构目录定稿后补全**；接手项目盘点后生成。子目录 `AGENTS.md`：**创建对应模块目录时写入**，新增模块同步新增。写作与维护细则 `agents-files.md`；红线只写所在层一处，下层不复制上层。

## 1. 七阶段流水线（每阶段出口过门禁评审 §6.4）

```
① 需求 PRD → FRD              → docs/01-需求/
   PRD：背景痛点 / 量化目标 / In-Out 范围 / 角色权限 / FR 编号 / AC / 领域依据
   FRD：FR→FP 追溯 / 字段与校验 / 规则顺序 / 状态流转 / 权限与数据范围 / 异常口径 / 验收映射
   ↓ 门禁：PRD 判「做不做、先做哪批」；FRD 判「研发能建实体与端点、测试能写字段级用例」
② 架构与技术选型               → docs/02-架构/
   总纲 + {X}工程化（含横切域：安全/可观测性/性能/成本）+ 选型表（开发默认 vs 生产标准）
   ↓ ★ 目录结构定稿 → 补全根 AGENTS     门禁：新人看图能说出每层职责
③ 契约冻结（最关键）           → docs/03-契约/ (+04-专项)
   数据模型 / API 与协议清单 / 错误码 / 专项接口
   ★ 并行支线：页面设计（docs/05-页面/）——IA/路由 → 布局稿（逐页区域/栅格/断点/四态布局/滚动归属）→ 逐页详设 → 组件清单；壳/token 引用 DESIGN.md
   ↓ 门禁：各端能并行开工，联调零歧义；**页面布局稿过审**（每页区域/栅格/断点/四态可判定，有浏览器实看或截图基准）
   ★ 同步起草：编码规范（§3.7）+ 执行步骤 + 开发顺序（契约冻结即可排活）
④ 分层实现                     → 代码目录
   建模块目录写子目录 AGENTS；按开发顺序波次推进；核心功能 TDD
   ↓
⑤ 质量门禁                     → docs/06-测试/ + 本地门禁
   测试金字塔 / 黄金集 / NFR 映射 / **页面布局与视觉回归（截图基准）** / 覆盖率 ≥80%（核心 ≥90%）
   ↓ 门禁：本地门禁能对反例红灯
⑥ 部署交付                     → deploy/ + docs/02-架构/部署工程化.md + 本地门禁命令清单
   环境矩阵 / 镜像 / 晋级回滚 / 本地门禁 = 同一组命令，不另建 CI（模板见 templates/DEPLOYMENT.md）
   ↓
⑦ 治理闭环                     → docs/07-治理/
   ADR / 执行步骤销项 / 评审记录 / 索引维护
```

**教学顺序提示**：用户跳过①②直接问「怎么写接口」→ 先追问需求和范围，否则契约会返工。
**项目当前阶段**：不写死在本库，以 `docs/07-治理/执行步骤.md` 与最新评审记录为准。

## 3. 各类文档与规范怎么写（模板索引 `templates/README.md`）

### 3.1 需求文档 PRD + FRD（→ `docs/01-需求/`）
阶段① 产出**两份互相追溯**的文档（缺一不可；极小项目可合并，但必须在 PRD 内保留「功能点级规格」节并声明合并理由）：

| 维度 | PRD（产品需求文档 `PRD-*.md`） | FRD（功能需求文档 `FRD-*.md`，Functional Requirements Document；勿与 FDR 混淆，FDR 通常指 Final Design Review，不是需求文档） |
|---|---|---|
| 回答 | 为什么做 / 给谁做 / 做成什么样算成功 | 每个功能具体表现成什么（系统行为规格） |
| 颗粒度 | 模块级 FR：业务规则 + AC + 批次 | 功能点级 FP：字段 / 校验 / 状态 / 权限 / 异常 / 输出 |
| 读者 | 决策者、产品、业务方 | 研发、测试、实施 |
| 不写 | 字段清单、状态机细节 | 表结构、技术选型、代码结构（进 02 / 03） |

**PRD 必含**：背景痛点（可量化）/ 产品目标（≥3 条数字指标）/ 范围 In-Out（含分期批次）/ 角色权限矩阵 / FR 编号功能 / 非功能需求 / 核心流程 / 验收 checklist / 分期路线 / **第一性原理（问题·约束·备选·非目标）/ 开放问题带推荐默认**。
**FRD 必含**：FR→FP 追溯总表 / 功能清单 / 全局通用规格（时间·金额·枚举·幂等·审计·错误信封）/ 逐功能点详设（输入字段与校验·处理规则·状态流转·输出与副作用·权限与数据范围·异常与错误码号段·并发幂等·AC 与 GT 预留）/ 跨功能约束 / 操作级权限矩阵 / 验收映射（FP↔AC↔GT↔端点/页面）/ 待定项（只引用执行步骤 §三 OP 台账）。

**阶段①门禁（两份都过）**：
- PRD：业务方能据此判断做不做、先做哪批；测试能只看 PRD 写业务级用例。
- FRD：研发能只看 FRD 建实体 / 端点 / 页面，不必再问产品；测试能只看 FRD 写出字段级校验与异常路径用例；**FR↔FP 追溯无孤儿**（FR 漏拆、FP 私加需求都必须为 0 或显式挂 OP）。

**红线**：每 FR 有可测 AC（数字/行为/错误码）；每 FR 至少一个 FP、每 FP 回指唯一 FR；FRD 只写「系统必须表现出的行为」，技术实现归 02-架构 / 03-契约；领域参数只引 SSOT 编号不复制数值；涉外部依据（法规/合同/平台规则）标注来源条款与生效口径；金额/比率写清算术口径（min()/上限分母）；PRD 与 FRD 冲突以 PRD 为准，口径分歧走 §5.4 拍板后回填。

### 3.2 架构文档 + {X}工程化.md（→ `docs/02-架构/`）
总纲必含：分层/上下文图（mermaid）、技术选型表（**开发默认**「本地能跑」vs **生产标准**「可扩展」）、工程原则（一句话级）、安全架构（权限收口点）。{X}工程化每个架构对象一份（后端/前端/部署/AI/数据…），**横切关注点同等对待**（安全/可观测性/性能/成本，各立一份或写进总纲节）。
**横切域红线**：口径一旦跨端（trace 头、日志字段、错误信封），必须同步落「契约文档一行 + 对应层级规范条款」——只有文档没有条款，实现必漂移；有审计/合规留痕的项目写清「审计事实 vs 运行日志」边界（存哪、留多久、靠什么 ID 关联）。
**mermaid 红线**：围栏内禁止裸文本（图例写围栏外；含 `=` 的裸行必报 parse error）；改完必须真实渲染自查。

### 3.3 数据模型（→ `docs/03-契约/`）
必含：ER 总览（标明行级隔离字段与外键关系）、可落库 DDL、关键口径注释、审计/幂等/软删策略。
**红线**：禁物理外键（ORM 逻辑关联）；软删 `deleted_at` 必须进唯一约束；索引有据可查、新查询 EXPLAIN 验证；审计表只追加；PII 字段标注脱敏策略；多份文档含实体清单时改一处查全部（防漂移）。ORM 项目：**表结构机读权威 = ORM schema**，本文档从 schema 回填、冲突以 schema 为准（§3.8）。

### 3.4 API 与协议契约（→ `docs/03-契约/`）
必含：基础约定（BaseURL、认证、统一信封）、**错误码号段表**、端点清单（方法+路径+入参+出参+错误码+权限）、流式/事件协议（若有）。AI Agent 项目另立专项接口清单（MCP Tools：每条目写权限注入、行级过滤、出参脱敏）。
**红线**：权限主体一律从认证凭据解析，不信任请求体；面向用户 msg 可操作；改端点 → 同一批变更更新文档 + manifest 自查。

### 3.5 测试方案（→ `docs/06-测试/`）
必含：测试金字塔与工具（按栈填）、**领域规则黄金集**（硬规则逐条：编号|依据|场景|输入|期望阻断/放行|错误码，期望写死数字边界不写两可分支）、覆盖对照表（规则↔用例↔模块，无孤儿）、**NFR 验证映射**（PRD §5 每条延迟/并发/RTO-RPO 数字 ↔ 验证方式，无映射即空头支票）、本地门禁清单、覆盖率阈值（≥80%，核心 ≥90%）。骨架见 templates/TEST-PLAN.md。

### 3.6 ADR 与评审记录（→ `docs/07-治理/`）
ADR：背景/决策一句话/备选对比/后果/状态流转（提议→接受→已落地→已废弃）。
评审记录：**结论先行**（可否进入下一阶段）→ 机械修复项（可直接改，修完销项）→ 需拍板项（列选项与影响，**AI 不私改**）→ 证据带 `file:line`；**遗留开放项只引用执行步骤 §三台账，不复制**。

### 3.7 项目编码规范（★ 写进对应层级 AGENTS.md + `.agents/rules/`，细则 `coding-standards.md`）
**规范不做成 skill**——skill 承载工作流（触发才加载，可能漏触发）；规范是约束性条款，必须**写进其生效层级的 AGENTS.md** 才稳定生效。落位两种形态：短条款直接写对应层级 AGENTS（全局适用→根，层级适用→子目录，每条 ≤1 行）；正文过长拆 `.agents/rules/*.md`（全局 1 份 + 每代码层级 1 份，frontmatter 声明作用域），AGENTS 留红线摘录（≤5 条）+ 必读引导。
生成四步（基线 `assets/通用编程规范与指南.md`，**不照抄**）：**按栈裁剪**（无关语言行删掉）→ **按架构补充**（从 02-架构 提炼分层边界、禁止模式、横切条款）→ **TDD 强制**（红→绿→重构；每测试一个行为；命名 `应该_预期行为_当_条件`；数字边界进黄金集）→ **落本地门禁**（能机检的沉本地门禁（lint），规范只留机检不了的）。生成时机：从零项目架构定稿后写码前；接手项目盘点后（**尊重现有风格**，差异标注棘轮收敛，不一刀切重构）。

### 3.8 数据访问规范（ORM 项目必守；全文 `data-access.md`）
口径两句：**表结构以 ORM schema 为唯一事实来源**（改表唯一路径 = 改 schema → generate 迁移 → 应用 → 回填文档；禁手写 DDL 平行定义、禁绕过 ORM 直连）；**数据访问优先查询构建器，SQL 只以参数化形式存在**（禁 `sql.raw()` 与字符串拼接；动态标识符走白名单；复杂 SQL 入仓储层并测试行级隔离断言）。落位：条款摘录进 `backend/AGENTS.md` 红线段 + 全文进 `.agents/rules/backend.md` 数据访问节 + lint 禁 raw 模式。

### 3.9 页面 IA / 布局 / 详设 + 视觉规范（→ `docs/05-页面/` + `.agents/designs/`）
四层一件：**页面设计.md**（IA + 路由表 + 页面↔验收锚点，路由是唯一真相，列表态进 URL query）→ **页面布局稿**（逐页区域划分 + 栅格/间距/断点 + 加载/空/错误/无权限四态布局 + 滚动与吸底归属 + 层叠关系；可并入详设 §3，也可独立 `页面布局-{端}.md`，但**必须逐页可落地，不能只有 P1–Pn 模式骨架**）→ **页面详设-{端}.md**（第一性原理推导 + 通用框架：页头/筛选/抽屉判定/表格/权限脱敏/四态 + 逐页区块/交互/硬阻断/GT + 组件清单）→ **DESIGN.md**（视觉 token 唯一权威：主题模型/色彩/字阶/密度/**布局框架冻结节**/可访问性/主权实现）。
**布局稿完成标准（缺一不进 ④）**：每页能回答「有哪些区域、每区放什么、栅格与断点怎么变、加载/空/错误/无权限各长什么样、滚动与吸底谁负责」；壳/滚动/token 引用 DESIGN.md 不复制数值；有浏览器实看或截图基准作为验收证据。
**红线**：壳结构、滚动主权、token 以 DESIGN.md 为唯一权威，页面文档**引用不复制**；硬阻断的 UI 呈现口径（错误码原文 + 可操作文案 + 禁现选项）必须在详设定死并同步落前端层级规范条款，否则 GT 前端验收必漂移。模板见 templates/PAGE-DESIGN.md / PAGE-LAYOUT.md / PAGE-DETAIL.md。

### 3.10 前端规范与实看验证（MCP 优先）（有界面项目必守；全文 `frontend-standards.md`）
（浏览器优先级按 Steward 口径：Playwright MCP / Chrome DevTools MCP → 内置浏览器兜底；证据写 `browser-evidence.json`。）

口径两句：**任何影响用户所见的前端改动，先判「增删改查」定级**（增 / 查 / 改 / 删 14 行分级表，判不准按更严一级），再按该行联动必改文档与必做验证；**必须按上方优先级实看并留四项证据**（入口 / 观察 / 截图 / 对照基准 + 所用工具；MCP 优先，内置浏览器兜底），只跑脚本或只看 diff 视同未验证，全不可用就停下报告未验证项、禁称「UI 正常」。落位：红线 ≤5 条进 `frontend/AGENTS.md`（含实看这条），正文进 `.agents/rules/frontend.md`（骨架 `templates/FRONTEND-RULES.md`），视觉只引用 `DESIGN.md` 不复制 token；能机检的（孤儿路由 / 硬编码色值 / 关键路径 E2E）沉本地门禁。生成项目版前端规范的四步（裁剪 → 补架构 → 落红线与正文 → 落本地门禁反证）见全文 §7。

### 5.2 接手存量项目（六步，细则 `takeover.md`）

盘点（通读 README/文档/代码/门禁，现状盘点表带 `file:line` 证据）→ 映射（现有文档按 01~07 出落位表，拍板后 git mv）→ 定位差距（判定走到七阶段哪里，列缺失清单）→ 补约束层（根/子目录 AGENTS + 编码规范（尊重现有风格）+ docs/README）→ 门禁评审（评审记录：当前阶段判定 + 机械修复项 vs 需拍板项）→ 进入常规流水线（执行步骤三表 + 剩余工序跨多模块时起草开发顺序）。
**红线**：先盘点后动手（外科手术式）；需拍板项不私改。

### 5.3 常见场景速答

- **从零写一份新文档**：查 §2 地图 → 定类型落子目录 → 按 §3 模板写 → 进 `docs/README.md` 与根 AGENTS 双索引 → 文档尾声明联动义务 → 自查（结构完整？AC 可测？mermaid 渲染过？无自相矛盾？）。
- **改代码时改文档**（最常见）：先读契约相关文档与数据模型 → TDD 先写测试（红）→ 实现到绿 → 同一批变更改契约文档 + manifest 自查 → 模块/命令变更同改 AGENTS → 贴测试真实输出 → 执行步骤销项。
- **发现文档与代码不一致**：**以代码为准回填文档**（提交/PR 描述写明「回填：原 X 现 Y」；默认不提交时写进 05-record）——除非安全红线或领域硬口径被破坏，则**停下讨论**；属需拍板的分歧（选型/归属/口径）列进评审记录等用户拍板，AI 不私改。
- **用户问「先写什么」**：按 §1 当前阶段答——没 PRD → 01；有 PRD 没 FRD → 01（把 FR 展开成功能点）；有 FRD 没架构 → 02；有架构没契约 → 03；契约齐 → 按开发顺序并行实现（改契约必须联动）；接手项目先走 §5.2 盘点。
- **存量文档迁移到子目录**：出映射表给用户拍板 → 建 01~07 子目录 → git mv（保历史）→ 建/更新双索引 → 更新互引路径 → 全局搜旧路径逐个替换（含 .agents/skills/）→ 检查本地门禁/docs-guard 硬编码路径。

### 5.4 需求 / 功能变更入口（★ intake：新需求、改口径、改范围必走）

```
触发：用户提出新需求 / 改功能口径 / 改范围批次
⓪ 提问预算（Steward Stage 0.1）：M/L / 二义 / 新领域先做第一性原理四问；最多 3 个 P0 问题，
   只问会改范围 / AC / 架构方向 / 合规红线的；P1/P2 按默认值记录，不阻塞；S 级不追问
① 影响面扫描：对照 §2 SSOT 地图 + §4 联动表，列出会动的全部产物
   （PRD FR / FRD 功能点 / 契约端点与错误码 / 数据模型 / 页面 / 黄金集 / 开发顺序波次 / 估算 / 种子数据）
② 需拍板项打包给用户：批次归属（进当前波次 or 延后）/ 口径选项 / 范围 In-Out / 工作量影响
③ 用户拍板：选型级落 ADR；需求级 bump PRD 版本 + 修订记录（改功能行为则 FRD 同批升版）；涉及契约则契约文档升版
④ 同一批变更联动落档：按 §4 全表执行 + 开发顺序重排留痕 + 执行步骤销项或挂账开放项
```
**红线**：不拍板不动文档；拍板结论必须留痕（ADR / 评审记录 / PRD 修订记录三者之一）；影响面清单里「不动」的产物也要点名（如「契约零改动」），防隐性漂移。

## 6. 工程管理规范（日常怎么守）

### 6.1 提交前自检清单
打印版全文（23 项：TDD 先行 / 变更入口拍板 / **PRD↔FRD 追溯** / 波次联动 / 数据访问红线 / 契约与参数联动 / 视觉联动 / **页面布局联动** / mermaid 渲染 / 模块与命令变更 / 执行步骤销项 / 开放项登记 / ADR / 可观测性联动 / 新硬约束落本地门禁 / 双索引 / 门禁链全绿 / 真实输出已贴……）见 `templates/PRE-COMMIT-CHECKLIST.md`。

### 6.2 AI 协作时的文档工作流
1. 回复开头声明：`对齐文档：docs/<路径> §<节> + Rules/Skill §<节>`。
2. 不凭记忆写文档内容——先 read 相关章节；**改代码前先读当前层级与根 AGENTS 规范条款及其必读的 `.agents/rules/` 正文**；任务先查 `.agents/skills/` 有无匹配技能。
3. 新代码文件写文件头注释：职责 + 核心链路 + 对齐文档章节。
4. 禁止用 `eslint-disable` / `noqa` / `type: ignore` 让门禁变绿。
5. 偏离文档/红线就停下说明，不猜。

### 6.3 可靠性排序（冲突时谁说了算）
```
本地门禁拦截 > pre-commit hook > lint/tsc 报错 > 根 AGENTS.md 红线 > 子目录 AGENTS.md > .agents/rules/ 规范 > README 正文 > docs/README 散文
```
文档写「必须 X」但无机器检查 → 迟早被忽略；优先把 X 沉进本地门禁/lint。

### 6.4 阶段门禁评审
1. **独立通读**全部相关源文档，不照抄前轮结论；清点关键数字（实体数/模块数/用例数/参数值），验证前轮结论的 `file:line` 引用，主动找遗漏。
2. 结论落 `docs/07-治理/评审记录-YYYYMMDD-<主题>.md`，**结论先行**：明确判定「可否进入下一阶段」。
3. 区分**机械修复项**（笔误/渲染错误/字段遗漏 → 可直接修，修完销项）与**需拍板项**（选型/归属/口径分歧 → 列选项与影响，等用户拍板，AI 不私改）；拍板后按 §4 联动同改并留痕。

### 6.5 文档与 AGENTS 维护（全周期）+ 实践回填
- 代码变更 → 受影响文档同步（§4）；新增/删除模块 → 对应层级 AGENTS 审核；启动命令/端口/依赖变更 → README + AGENTS 命令速查同步；红线增删只改所在层一处；版本 bump → 文档头部状态行 + docs/README 状态列 + 执行步骤盘点。细则见 `sync-rules.md`、`agents-files.md`。
- **实践回填**：项目跑通的新产物/新口径验证有效后回填本库对应模板与章节（在评审记录留痕改了什么）——本库的开发顺序模板、三表执行步骤、数据访问规范均由项目实践回填而来。

## 7. 常见错误与修复

| 错误 | 症状 | 修复 |
|---|---|---|
| 文档散落 docs/ 根 / 复制粘贴 | 阶段归属不清；同一参数 3 处漂移 | 迁子目录（§5.3 先拍板）；收敛 SSOT 改引用 |
| 跳过需求直接写接口 | 范围蔓延、接口反复改 | 回 §3.1 补 PRD 最小集 |
| **只有 PRD 没有 FRD（或 FRD 只抄 PRD）** | 字段 / 状态 / 异常各写各的，联调才暴露口径不一致；AC 与用例对不上号，GT 无落点 | 按 §3.1 把 FR 展开成 FP：字段与校验 / 规则顺序 / 状态流转 / 权限与数据范围 / 异常口径 / AC↔GT 映射；建 FR↔FP 追溯表 |
| **只有 IA/路由和 P1–Pn 模式骨架，没有逐页布局稿** | 各页各写一套区域/间距/断点；壳对了但页面布局漂移；视觉验收没有基准 | 按 §3.9 补逐页布局稿（区域/栅格/断点/四态/滚动归属），过布局门禁再进 ④；⑤ 加截图基准回归 |
| **FRD 写成技术设计** | 表结构、框架选型混进需求；改口径要看代码，需求被实现细节绑架 | FRD 只写系统必须表现出的行为；表 / 端点 / 选型进 02-架构 与 03-契约 |
| 只写文档不落门禁 | 规范无人遵守 | 关键项写成本地门禁（lint）（对反例能红灯） |
| 编码规范照抄通用基线 | 规范里全是项目用不到的语言 | §3.7 四步：裁剪→补充→TDD→落本地门禁 |
| 规范做成 skill / AGENTS 塞长正文 / 子目录复制根红线 | 约束漏生效；每轮注入开销大；双份漂移 | 条款进 AGENTS、正文拆 rules；skill 只放工作流；下层只写本层新增 |
| 绕过 ORM 直连 / `sql.raw()` 拼 SQL | 注入面；schema 与库漂移；查询无权限断言 | 回 §3.8 + `data-access.md` |
| 可观测性只在部署图留开放项 | 故障无法还原、trace 断链、日志成 PII 旁路 | ② 立横切域文档：贯穿链 + 字段字典 + 告警三要素 + 审计边界 |
| **新需求直接写文档不拍板** | 决策被架空、范围蔓延 | 回 §5.4 变更入口：影响面 → 拍板 → 留痕 → 落档 |
| **开发顺序与执行步骤混用 / 开放项散落** | 排活与进度纠缠；待定项失控 | 开发顺序管排活、执行步骤管进度（§0.2）；开放项唯一台账在执行步骤 §三，统一编号 |
| **本地门禁两套口径** | 本地绿、换台机器红 | 本地门禁 = 同一组 Taskfile/脚本命令，不另建 CI（templates/DEPLOYMENT.md） |
| mermaid 围栏内塞图例文字 | 渲染 parse error | 图例移围栏外，渲染自查 |
| 新文档不进索引 | 下次没人找得到 | 同步 docs/README.md + AGENTS 索引 |
| 把需拍板项私自改掉 | 决策被架空 | 回滚，列评审记录等拍板 |
| 接手项目先大改 / 顺手改产品 harness 目录 | 破坏未知依赖；越权动人配置层 | 先盘点后动手；停手只提议由人执行 |
| **代码文件按波次 / 阶段编号命名** | `w8s4.op142.foreman-convergence.test.ts`、`seed-w6.ts`、迁移目录 `..._w7_2_overtime_remark`；波次关闭后文件名失去语义，下一批继续往上叠 | 回 §0.3：按业务 / 行为改名，阶段归属留在执行步骤与评审记录；存量用命名守卫 + 基线 burn-down（`naming-guard.md`） |

```
输入：用户说「加一个 POST /refunds 发起退款，超100元要审批」

0. ★ 变更入口（§5.4）：影响面扫描——PRD（新增 FR + AC + 批次归属）、FRD（FR→FP 展开：
   字段 / 规则 / 状态 / 异常）、契约（端点+错误码+可能的 approvals 表）、页面（若有 UI）、
   黄金集（>100 必拦用例）、开发顺序（进哪一波）、种子数据；需拍板项（批次归属 /
   审批人角色口径）列给用户 → 拍板后才动文档
1. 补 FR-x.y 进 PRD（输入/规则/AC/批次），再在 FRD 补 FP-x.y 与追溯行；两份同批 bump 版本 + 修订记录
2. 查架构：退款归哪个模块/层（工程化文档分层职责）
3. 冻结契约：ER 确认 approvals 字段与行级隔离；API 文档写端点+错误码；
   Agent 可发起 → 专项接口清单加条目
4. TDD 实现：先写测试（发起/超限必拦/越权，红）→ services + 薄 endpoint（绿）

6. 联动（一批变更）：API 文档、执行步骤销项、（UI）05-页面 + designs、
   （新模块/命令变化）AGENTS.md、开发顺序波次挂账
7. 验证：贴测试输出 + manifest 自查 + 门禁链结果
```
