# 项目记忆（memory）

长期项目的最大成本是"知识只存在于某次对话里"。本文件管「该不该记、记在哪、怎么不断链」：记忆载体、决策、状态与上下文。

> **与 [documentation.md](documentation.md) 的分工**：本文件回答「记什么、放哪」；文档治理回答「记下来之后怎么不长成屎山」——三类文档分治、体积预算与拆册、读契约、版本快照与溯源、归档轮转都在那边。同一条规则只定义一次，这里只留指针。

## 1. 发现顺序

创建任何新文档前，按顺序找现有载体：

1. 仓库指令：`AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING.md`、`.github/` 模板。
2. `README` 与 `docs/`：安装、架构、API、运维、ADR、路线图。
3. `CHANGELOG`、发布说明、issue/PR 模板。
4. 代码内注释与测试名（也是事实来源，但优先修正到文档）。

已有载体就沿用其结构与命名；没有才创建最小集。

## 2. 最小常青集

| 工件 | 类 | 回答的问题 | 位置建议 | 更新时机 |
|---|---|---|---|---|
| 项目简报 | 活 | 是什么、给谁、成功标准、不变量、命令 | `docs/project-brief.md` 或 README | 方向/架构/命令变化 |
| 决策记录（ADR） | 记录 | 为什么这样选，放弃了什么 | `docs/decisions/NNNN-*.md` | 满足门槛的决策 |
| 变更日志 | 记录 | 用户/集成方感知到什么变化 | `CHANGELOG.md` | 每次对外可见变更 |
| 当前状态/交接 | 临时 | 现在做到哪、下一步、风险 | `.agents/state/current.md` 或 issue | 每个里程碑 |
| 运行手册 | 活 | 怎么部署、回滚、排障 | `docs/runbook.md` | 运维方式变化 |

不是每个项目都需要全部；但跨会话、多人协作或长期维护的项目，至少要有简报、变更日志与状态。第三类**基线文档**（需求规格、数据模型、有冻结语义的契约）只在需要跨版本溯源时建，见 [documentation.md §1](documentation.md)。

## 3. 项目简报

一页以内，模板见 `assets/project-brief.md`（相对技能根目录）。必须包含：

- 问题与用户；成功标准与非目标。
- 架构鸟瞰与关键模块；数据流。
- 不变量与契约（绝不能破坏的规则）。
- 命令：安装、运行、测试、构建、发布。
- 环境、外部依赖、部署与回滚方式。
- 已知风险与限制。

保持更新；过期比没有更危险。

## 4. 决策记录（ADR）

何时写（满足任一）：

- 难以回滚（数据模型、公共 API、平台选型）。
- 跨模块/跨团队影响。
- 实施成本超过 1 天。
- 限制未来选项或引入长期维护负担。
- 团队有分歧，需要留下理由。

格式：标题、状态（提议/已接受/已取代/已弃用）、日期、背景、决策、备选方案、后果（正面/负面/风险）、迁移与回滚、关联链接。模板 `assets/decision-record.md`。

规则：一号一决策；不可变（修订用新 ADR 取代）；放在版本库；在代码/PR 中链接相关 ADR。索引、归档轮转与「文件头状态 ↔ 索引状态」双向一致的要求见 [documentation.md §5](documentation.md)。

## 5. 变更日志

- 面向用户与集成方，不写内部重构流水账。属**记录类文档**：只增不改，每条写清影响与迁移方式。
- 分类：Added / Changed / Deprecated / Removed / Fixed / Security。
- 每条说明影响与迁移方式；破坏性变更显著标注。
- 版本号遵循仓库策略（通常语义化版本）；未发布内容放 Unreleased。
- 发布时从 changelog 生成发布说明，不重复维护两份。

## 6. 状态与交接

临时状态（当前任务）建议放 `.agents/state/current.md`，可加入 `.gitignore`；它不是团队知识的唯一载体。

内容：目标、模式、已完成、证据、未决问题、下一步、关键文件/命令、风险。每个里程碑更新一次；任务结束归档或删除。

交接必须自包含：接手者不看历史对话也能继续。模板 `assets/handoff.md`。重要决策同时写入 ADR/文档，不能只留在状态文件。

## 7. 上下文管理

- **按需读取**：先目录/搜索定位，再读相关片段；不要一次性倾倒大文件。
- **写下来**：决策、路径、命令、证据在里程碑处落盘，抵抗上下文丢失。
- **压缩优先级**：决策与理由 > 文件路径与命令 > 验证结果 > 未完成项 > 过程叙述。
- **恢复协议**：读状态 → `git status/log` → 复跑最快门禁 → 确认假设 → 继续。
- **批次化**：把同类小操作合并，减少往返；但验证不能省。
- **避免上下文腐烂**：长会话中定期重读关键文件与状态，不凭记忆编辑。

## 8. 文档漂移检查

- README 的命令在干净环境跑一遍（至少每月或每次发布前）。
- 架构图/模块说明与目录结构对照。
- API 文档与实现/契约测试对照。
- 链接检查（相对路径、外部链接）。
- 体积预算：活文档是否超限、是否该拆册、超限项有没有登记。
- 读契约：文档头字段是否还在，`status: archived` 与所在目录是否矛盾。
- 版本一致：文档头版本 = 修订表最新行 = 历史索引最新行。
- 历史区：快照哈希与清单是否一致，同一主题是否只剩一份现版。
- 过期截图与版本号清理。
- 发现漂移按缺陷处理：修文档或修代码，二选一并记录。
