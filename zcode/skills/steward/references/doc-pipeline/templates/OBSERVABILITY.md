## 可观测性与日志工程化.md 模板（`docs/02-架构/`，横切域）

> 触发：项目有后端服务、定时任务、外部依赖或任何运维面——没有它，故障无法还原、日志易成 PII 泄漏通道。
> 核心是两件事：**一条贯穿链**（谁生成 trace → 怎么透传 → 落哪些字段与表）与**一张边界表**（合规留痕 vs 运行日志）。审计/留痕已由业务契约定义时，本文只写边界 + 关联键，**不重复建设**。

| 字段 | 内容 |（文档性质 / 适用范围：哪些部署单元 / 上游引用 / 下游落点）

> 一句话：本文是运行期可观测性的唯一权威；审计/合规留痕权威在数据模型文档，两者边界见 §2，引用不复制。

## 1. 第一性原理推导（公理 → 决策）
<公理候选（按项目实况裁剪）：可举证优先 / 分布式端到端关联 / 无人值守主动暴露 / 数据最小化与留存有界 / 不绑厂商可演进>
<推导：审计与运行日志分家 → trace 贯穿 → 告警第一实例 → PII 禁入 → stdout JSON 基线；越档位的（APM/tracing 平台/采集栈）列「立项先 ADR」>

## 2. 边界：合规留痕（审计）vs 运行日志

## 3. 三支柱分级（开发默认 vs 生产标准）
<日志（stdout 单行 JSON → 集中采集）/ 追踪（关联 ID 贯穿 → OTel 兼容采集）/ 指标（从哪里取 → 采集栈）>

## 4. 关联 ID（trace）贯穿链

<闭环示例：报障 → trace → 全链路日志 → 审计行>

## 5. 结构化日志规范

<级别语义表（可判定）；禁止项：PII/凭证/完整请求体/日志当第二数据通道/静默降级>

## 6. 指标与告警
