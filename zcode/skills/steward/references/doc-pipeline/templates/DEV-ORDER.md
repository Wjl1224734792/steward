## 开发顺序模板（`docs/07-治理/开发顺序.md`）

> 定位：实现阶段的**开工顺序 SSOT**——功能模块排序（依赖倒逼）+ 每波前后端拆分 + 并行规则 + 估算。契约冻结（③ 出口）后起草（与执行步骤同时），全周期维护：**范围/依赖/波次变更必须重排并在执行步骤留痕（同一批变更）**。与执行步骤分工：本文管「怎么排活」（低频改），执行步骤管「做到哪了」（每次变更动）。

```markdown
# 开发顺序（按功能模块 · 前后端拆分）
> 头部字段表：文档性质 ｜ 版本 ｜ 适用范围（批次——第 2 批与延后批次不在内，启动前各自出 ADR）
> ｜ 上游（PRD·契约·页面·ADR·执行步骤）｜ 下游（代码目录 + 执行步骤销项指针）
> ｜ 约束（每波次结束门禁链全绿才算完成；改本文件 = 同一批变更改执行步骤.md 销项状态）

## 1. 排序原则（第一性原理）
<依赖倒逼排序：模块顺序 = 数据依赖链的反向拓扑序——主数据不先行，其后所有模块的行级过滤都是空中楼阁；
 合规硬阻断随模块自然落位、不单独排期——阻断规则是模块行为的一部分，随垂直切片 TDD 落地，拆「合规专项」制造无人认领的缝；
 垂直切片优先于层级推进——每波次 = 一个后端单元 + 对应页面 + 测试，一批变更闭环；禁止「后端全做完再回头做前端」（联调风险后移是大工期杀手）；
 契约冻结使前后端可解耦并行——照契约 schema + mock 层先行，同波次 BE 先行 2~3 个工作日；
 GT/验收锚点是波次验收最低配——黄金集期望值已锁的随波次落，悬置的按 ADR 留痕不阻塞>

## 4. 每波前后端拆分明细
<每波一节：| 侧 | 项 | 内容与验收 |——BE 端点/事件/硬阻断落点、FE 页面、验收标准>

## 5. 并行与单独推进规则
<双轨制（BE 先出 store+端点+单测，FE 照契约 mock 先行，端点绿了再联调）；
 FE 可整体先行一层（但硬阻断呈现/错误码文案必须等 BE 落位联调，防口径漂移）；
 可并行的独立线（引擎/基建/文案）排进空档不占关键路径；单独后端波次（无 FE 依赖面的）；
 联调缓冲 ~15%；首波次结束按实测速度校准，偏差 >30% 重排本表>

## 6. 估算基准
<端点行 × 人天/行（CRUD 类 ~ 合规计算类）；页面 × 人天/页；集成测试按复杂度另计；
 人力假设（双轨/单人）；明确不含的批次>

## 7. 双轨甘特（波次 ≥3 时值得画）
<mermaid gantt：BE 轨 / FE 轨分 section；同波次 BE 条先起、FE 条晚 ~2 工作日；渲染自查>

## 8. 波次开工前置（kickoff checklist，每波开工前逐项确认）
- [ ] 本波契约段已冻结（契约文档 + 机读 schema 同步）
- [ ] 数据基础就绪：依赖波次的 schema/迁移可应用、种子数据可用
- [ ] FE mock 层覆盖本波端点（照契约 schema 生成）
- [ ] 新模块的子目录 AGENTS.md 与必读规范已就位
- [ ] 测试锚点明确：本波 GT 黄金集期望值已锁定或按 ADR 留痕
- [ ] 门禁链本地全绿基线（开工点可回退）

## 9. 联动义务
| 改了什么 | 同一批变更必改 |
|---|---|
| 波次顺序 / 模块归属 / 估算 / 依赖 | 本文件 + 执行步骤.md（销项状态） |
```
