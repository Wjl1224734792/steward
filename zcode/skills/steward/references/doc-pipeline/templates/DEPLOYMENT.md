## 部署工程化.md 模板（`docs/02-架构/`，阶段⑥ 主产物）

> 触发：首次发版前必建；开发期只有本地 compose 也先开档记现状（02-架构 列名即开档）。它管「代码怎么变成在线服务」：部署单元与环境矩阵、配置与密钥、镜像、晋级与回滚、本地门禁清单、NFR 落位、新人 runbook。
> 原则：**本地门禁 = 同一组 Taskfile/脚本命令**——本地与提交前钩子跑同一套命令，不另建 CI，杜绝「本地一套、门禁一套」两套口径。

```markdown
# 部署工程化
> 版本 | 日期 | 状态 ｜ 适用范围：全部部署单元

## 1. 部署单元与镜像
| 单元 | Dockerfile | 基础镜像 | 健康检查（/healthz·/readyz） | 构建实证 |
<每单元一行；多阶段构建 / 非 root / 优雅停机等共性写一行说明>

## 2. 环境矩阵
| 环境 | 用途 | 数据（可丢？） | 谁可部署 | 配置来源 |
<dev（本地 compose）/ SIT / PRE / PROD；每环境写配置文件路径与注入方式>

## 3. 配置分层与密钥红线
<优先级：环境变量 > 环境配置文件 > 默认值；同一配置项只一个权威来源；
 密钥/口令永不进仓库（.env.example 占位，部署时注入）；配置文件版本化>

## 4. 晋级路径与发布
<dev → SIT → PRE → PROD；每级门禁（SIT=门禁链全绿 / PRE=验收通过 / PROD=拍板）；
 版本策略：迭代号或 SemVer + tag 规范 + 发布记录（CHANGELOG 或 07-治理 评审记录，项目拍板一处）>

## 5. 回滚
<回滚 = 上一镜像 tag 重部署；数据库迁移兼容策略（向后兼容迁移/破坏性变更两段式）；
 回滚演练要求与演练记录>

## 6. 本地门禁命令清单（可选 git hook）
<必过步骤：lint → typecheck → test（含集成，需 Docker）→ build → 镜像构建 → 自制门禁（docs-guard / doc-check / guard-naming 等）；
 全部步骤调用同一 Taskfile 任务，不出现第二套命令；
 默认不创建 .github/workflows；需要提交前拦截时启用可选 pre-commit hook，跑同一组命令；
 多人协作可加 CODEOWNERS，但门禁仍以本地脚本为准>

## 7. RTO/RPO 与容量（PRD §5 NFR 落位）
<每条 NFR 数字映射部署方案：备份策略与频率 / 单点与冗余 / 扩容阈值；
 无数字的列开放项进执行步骤 §三>

## 8. 本地起步 runbook（新人 Onboarding）
<infra-up → 迁移 → seed → 门禁链 → 本地启动 → 常见故障三条；命令与 README/AGENTS 命令速查同源引用>

## 9. 联动义务
<镜像/端口/启动命令变更 → 本文件 + AGENTS 命令速查 + README；环境增删 → §2；晋级/回滚流程变更 → §4/§5>
```
