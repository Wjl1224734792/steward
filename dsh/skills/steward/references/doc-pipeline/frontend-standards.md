# 前端规范与实看验证规程（MCP 优先；有界面项目必守）

> 适用：任何有用户界面的项目（web / h5 / 桌面端 / 小程序 / 大屏）。核心口径两句：
> **① 任何影响用户所见的前端改动，先判「增删改查」定级，再按级走必改文档与必做验证**；
> **② 必须用实看（MCP 优先）验证，不允许只凭代码审查或单测宣称「UI 正常」**。
> 本文自 README.md §3.10 外移（编号不变，正文唯一权威在此）；生成项目版前端规范的四步见 §7，落位通道见 README §3.7（条款进 AGENTS / rules）。

## 0. 落位结构（前端约束住哪）

| 内容 | 落位 | 说明 |
|---|---|---|
| 前端红线（≤5 条，每条 ≤1 行） | `frontend/AGENTS.md`（或项目实际前端目录名）红线段 | 含「影响用户所见的改动必须实看（MCP 优先）」这条 |
| 前端规范正文 | `.agents/rules/frontend.md`（骨架见 `templates/FRONTEND-RULES.md`） | 每代码层级 1 份，frontmatter 声明 `globs: frontend/**` |
| 视觉 token / 主题 / 布局框架唯一权威 | `.agents/designs/DESIGN.md` | **不复制进 rules**——rules 只写「怎么用」，色值一律去 DESIGN.md 查 |
| 页面 / 路由 / 组件事实 | `docs/05-页面/`（页面设计路由表 + 详设分册） | 代码里的路由表与文档是双向可核对的 |
| 接口字段 / 错误码 | `docs/03-契约/` | 前端类型定义从契约生成或手工对齐，不自行发明字段 |

**红线**：规范不做成 skill（会漏触发）；条款进 AGENTS 稳定生效，正文进 rules 渐进披露（`coding-standards.md` §0）。

## 1. 增删改查分级表（★ 一切前端改动的判定入口）

动手前先在下面表里定位「我这次是哪一级」，按该行的「必改文档」与「必做验证」执行；命中多行就全做，验证取并集；**判不准按更严的一级执行**。四类顺序即 **增 → 查 → 改 → 删**，与日常开发动作同构。

| # | 级别 | 判定（命中任一即算） | 必改文档（同一批变更） | 必做验证 |
|---|---|---|---|---|
| 1 | **增**·新页面/新路由 | 加了路由条目、加了页面目录 | 页面设计路由表 + 详设新增页 + 组件清单 + `docs/README.md` 索引（新端则新开详设分册） | 实看（MCP 优先）四态 + 该页 E2E 冒烟 |
| 2 | **增**·新组件 | 新增 shared / features 组件或工具 hook | 详设组件清单 + `前端工程化.md` 目录约定 +（产生新约定→rules 条款） | 实看（MCP 优先） + 组件测试（渲染 + 一个关键交互） |
| 3 | **增**·新数据获取 | 新增写操作请求、新增端点调用、新增 mock | API 契约 + mock 层（+ 新增字段→数据模型） | 实看网络面板：请求发出、响应处理、错误分支 |
| 4 | **查**·新列表/详情/报表页 | 新增只读页面、报表、看板、明细页 | 路由表 + 详设新增页 + 组件清单 + GT/AC 落点 | 实看（MCP 优先）四态（**必区分「暂无数据」与「筛选无结果」**）+ 翻页/下拉实看 |
| 5 | **查**·查询口径 | 加或改筛选、排序、分页、字段显隐、默认排序、搜索 | 页面设计 §1（**列表态一律进 URL query**）+ 契约端点入参 + 详设查询区 +（新枚举→参数 SSOT） | 实看（MCP 优先）筛选/排序/分页 + **带 query 直链打开仍能还原同一结果** |
| 6 | **查**·导出/下载/打印 | 新增导出、下载、打印、分享链接 | 契约端点 + 权限校验口径 +（大数据量→后台任务与状态轮询口径） | 实看（MCP 优先）「有权」与「无权」两条路径 + 下载产物确实可打开 |
| 7 | **改**·结构/交互 | 改区块构成、抽屉↔整页判定、改表单字段、改校验 | 详设对应页 +（动到壳结构→`DESIGN.md` §布局框架 + 页面设计 §2） | 实看（MCP 优先）交互全流程 + 四态 |
| 8 | **改**·视觉/样式 | 改色值、字号、间距、密度、动效 | **`DESIGN.md` token 与代码同一批变更改**（禁只改代码不改 token） | 实看（MCP 优先） + 双主题 + 双视口 |
| 9 | **改**·路由/IA | 改路径、改菜单、改标签/面包屑派生规则 | 页面设计路由表 + 详设 +（可见性按角色→安全架构口径） | 实看（MCP 优先）导航 + 深链直达 + 面包屑 |
| 10 | **改**·呈现口径 | 改错误码呈现、空态、无权限态、加载态文案与行为 | 详设硬阻断节 + **前端层级规范条款** +（涉契约→API 文档） | 实看（MCP 优先）该状态 + 错误码原文逐字比对详设 |
| 11 | **改**·性能敏感 | 改大列表、动画、首屏、长任务 | `前端工程化.md` 性能节 +（有 NFR 数字→测试方案 §4 映射） | 实看（MCP 优先） + 度量数据（不是「感觉不卡」） |
| 12 | **删**·页面/路由 | 下线页面、下线菜单入口 | 路由表删条目 + 详设删页 + GT/AC 落点核对 + 菜单/面包屑/权限白名单 + `docs/README.md` | 构建零残留引用 + **旧链接行为已确认**（404 / 重定向到哪，口径写死） |
| 13 | **删**·组件/工具函数/样式 | 删除被引用的复用件 | 先改引用者 → 再删本体；详设组件清单同步 | 构建零残留引用 + 所有引用页实看 |
| 14 | **删**·字段/枚举值 | 接口出参删字段、状态枚举删值 | API 契约 + 数据模型 + 前端类型 + 使用处 + 黄金集 | 相关页面实看 + 契约机检（manifest diff） |

**分类速判**：拿不准「改」属于哪一层时，先问自己改的是 **数据层 / 交互层 / 视觉层 / 路由层**，对应第 3/7/8/9/10 行——先分类再选行，避免「顺手改」跨行漏联动。
**「查」最易漏**：只读改动不写代码也能改口径——加一个筛选条件、换一个默认排序、把字段显隐收起来，都会动契约入参与页面设计 §1；空态从「筛选无结果」退化成「暂无数据」是最高发的漏联动。

**红线**：
- **删**必须先搜引用（`import` / 路由表 / 文档互引 / 权限白名单 / GT 锚点），残留引用构建必红；**禁先删代码后补文档**。
- **改视觉**反向也要联动：代码里的色值必须能在 `DESIGN.md` 找到出处，找不到就是新 token，走提案→拍板→同一批变更落档（§4）。
- **查**的口径写死在一处：列表态只认 URL query，不在组件内另存一份，也不只在 store 里存。
- 新增页面若改变用户任务路径 → 属需求变更，先走 README §5.4 变更入口，不在本表内自决。

## 2. 实看（MCP 优先）验证规程（★ 红线）

> **Steward 口径：优先 Playwright MCP / Chrome DevTools MCP**（读 accessibility tree、console、network），MCP 不可用才退回内置浏览器；两者都不可用才用人工截图。证据统一写 `browser-evidence.json`，`fallbackUsed` 如实记录。

### 2.1 何时必须实看（强制，不接受「这次改动太小」）

- §1 分级表命中任一行（增 / 查 / 改 / 删）→ 必看；
- 交付「已完成 / 已修复 / 可以验收」结论前 → 必看；
- 回归：改动波及的**其他页面**（共享组件、共享 hook、全局样式、token 一律波及所有引用页）→ 必看；
- 门禁评审 / 自证交付 → 必开。

### 2.2 工具优先级（MCP → 内置浏览器 → 人工截图）

1. **默认：Playwright MCP / Chrome DevTools MCP**——能读 accessibility tree / console / network，证据最硬；
2. 降级 1（仅当 MCP 不可用）：内置浏览器——可视、可真实点击与输入；
3. 降级 2（仅当前两者都不可用）：由人提供截图 / 录屏作为证据；
4. **全部不可用 → 停下明确报告「本次无法实看验证 UI」**，逐条列出未验证项并请用户确认，**禁止**宣称 UI 正常、禁止说「应该没问题」。

> 用了哪一级工具必须写进 `browser-evidence.json` 的 `provider` / `fallbackUsed`（§2.4 第 4 项）。**只贴代码 diff 或只跑脚本、没有可读状态证据，视同未验证。**

### 2.3 验证矩阵（每次改动至少覆盖的格）

| 维度 | 取值 | 何时必查 |
|---|---|---|
| **四态** | 正常 / 空 / 加载中 / 错误 / 无权限 | 每个数据页面必查（详设 §2 四态模板为准） |
| **视口** | 桌面主视口 + 至少一个窄视口 | 响应式项目必查；`05-页面/` 定义了多端的按端查 |
| **主题** | 亮色 + 暗色 | 项目有主题切换必查 |
| **数据形态** | 正常值 + 边界值（空数组、超长文本、极值数字、缺字段） | 列表 / 表单 / 详情页必查 |
| **联调** | 请求发出 + 响应处理 + 错误处理 | 涉及接口必查（看控制台与网络面板） |
| **权限** | 有权 + 无权（展示控制） | 涉及角色差异必查；**权限最终以后端为准**，前端只是展示控制 |

### 2.4 证据留存（禁止「我看了一眼」）

每次实看必须留下**可复核证据**，四项缺一不可：

1. **入口**：URL（含路由）+ 视口尺寸 + 主题 + 操作路径（点了什么）；
2. **观察结果**：按 §2.3 矩阵逐项勾选，不写「正常」两个字了事；
3. **证据**：截图 / 录屏落 `tmp/verify/YYYYMMDD-<主题>/`（勿散落仓库根）；控制台与网络的结论贴原文而非转述；
4. **对照基准 + 用了什么工具**：比对的 `DESIGN.md` token / 详设条目号，并写明「符合 §x」还是「与 §x 不一致」；同时注明用的是 **MCP / 内置浏览器 / 人工截图**（及降级原因），写入 `browser-evidence.json` 的 `provider` / `fallbackUsed`。

证据文件格式以 Steward `browser-evidence.json` 契约为准；本节四项是该文件的补充检查清单。

截图可清理，**结论文字必须留在评审记录或执行步骤里**（`docs/07-治理/`）——否则事后无法复核。

### 2.5 常见违规与后果

| 违规 | 为什么不行 |
|---|---|
| 只改代码不看效果 | 布局错位、溢出截断、层级混乱、主题对比度不足，只有渲染才暴露 |
| MCP/内置浏览器能开却不开 | 证据最硬的手段没用上，等于主动放弃了最强验证；只跑脚本或只看 diff 不等于实看 |
| 只看正常态 | 空态 / 错误态是事故高发区，也是 GT 锚点落点 |
| 只看改动页 | 共享组件与 token 改动会波及没改的页面 |
| 用「应该没问题」代替结论 | 不可复核，等同没验证 |
| 代码改了色值但 `DESIGN.md` 没改 | 视觉口径漂移，下一轮没人知道这个值从何而来 |
| 浏览器报错当噪音跳过 | 控制台报错常是真实缺陷的唯一线索 |

### 2.6 实看与 E2E 的分工（不互相替代）

| | 实看（§2） | E2E（本地门禁） |
|---|---|---|
| 覆盖 | 视觉合理性、异常组合、新交互、跨主题跨视口 | 关键路径稳定复现、防回归 |
| 时机 | 每次改动 | 提交 / 门禁 |
| 规则 | 必做（§1 命中即触发） | 新页面、关键路径改动必须同时补 E2E 用例，并进 `docs/06-测试/` 覆盖对照表 |

## 3. 组件与状态规范

1. **组件边界**：一个组件只做一件事；容器组件只编排不写业务判断；业务判断下沉到 hook / 领域函数（对齐 `前端工程化.md` 分层）。
2. **状态归属**：就近原则——局部 UI 态（展开、悬停、输入中）留在组件内；跨组件共享态（会话、主题、当前筛选）才上提；**服务端数据不复制进本地 store**（单一数据源，防双份漂移）。
3. **数据获取**：请求在数据层 / hook，组件内禁止直接 `fetch` / 直接调 SDK；查询参数（筛选、分页、排序、tab）进 URL query 派生，不在 store 另存一份。
4. **四态**：每个数据组件必须有 loading / empty / error /（no-permission）；空态要区分「暂无数据」与「筛选无结果」并给可操作动作，不许一个空态糊弄两种语义。
5. **错误呈现**：错误码原文 + 可操作文案 + 禁现选项，SSOT 在详设 §2；**组件不自行编文案**，未在详设定义的错误呈现属口径缺失 → 停下补文档，不就地发挥。
6. **不可变与 key**：状态更新返回新值，不就地改；列表 `key` 用业务稳定 ID，**禁用数组下标**（列表会插删时会串行错位）。
7. **副作用清理**：订阅、定时器、事件监听、observer 在卸载时释放（泄漏表现为切页后仍在请求 / 内存涨）。
8. **组件测试**：每个组件至少覆盖「渲染正确 + 一个关键交互或状态」；组件里承载领域规则数字边界的分支，必须同时进黄金集（`docs/06-测试/`）。

## 4. 样式与 token（引用基线，不复制）

- **三层颜色键**（primitive → semantic → component）与「配 UI 框架时映射框架 token、不另起炉灶」：全文见本技能 `assets/coding-guidelines-baseline.md` §2.9，**这里只写项目落地口径，不复制色值与示例**。
- **主权**：主题收敛到 Provider（如 antd `ConfigProvider` token）；禁全局组件类覆盖、禁第二套色板、禁组件里散落魔法数。
- **token 变更路径**：提案 → 用户拍板 → `DESIGN.md` + 主题稿 + 代码**同一批变更** → 受影响页面实看（§2）→ 同步 `rules/frontend.md` 若有新增使用约定。
- **代码里的色值必须能反查到 `DESIGN.md`**；反查不到 = 新 token，先补文档再改代码。
- 基线的通用禁令（禁 `@apply`、禁运行时 CSS-in-JS、全局样式最小化）按项目栈取舍；项目有例外必须在 `rules/frontend.md` 注明**原因**，不写「视情况」。

## 5. 性能与可访问性底线

| 项 | 底线口径（项目写具体数字） |
|---|---|
| 长列表 | 超 N 行启用虚拟化 / 分页，N 写进 `前端工程化.md` |
| 首屏 | 关键请求数与包体预算写进 NFR，并在测试方案 §4 映射验证方式 |
| 图片 | 尺寸声明 + 懒加载 + 现代格式 |
| 动画 | 只动 transform / opacity；尊重 `prefers-reduced-motion` |
| 键盘与焦点 | 全部交互元素键盘可达、焦点可见、Tab 顺序合理 |
| 对比度 | 正文与背景达到 DESIGN.md §4 声明的档位（WCAG 档位写明，不写「差不多」） |
| 表单与图标 | 表单控件有 label 关联；纯图标按钮有可读名 |

**红线**：a11y 与性能数字不是「建议」，须落进 `DESIGN.md` §4 与测试方案 NFR 映射——否则是无法验证的口号。

## 6. 落本地门禁（能机检的不写文档）

| 约束 | 机检方向 |
|---|---|
| 禁硬编码色值 / 魔法数 | eslint 自定义规则 · stylelint |
| 禁 `console.*` / `debugger` | eslint `no-console` |
| 禁 `eslint-disable` / `@ts-ignore` 骗绿 | eslint 禁用指令上报 + 本地门禁抽查 |
| **孤儿路由双向核对** | docs-guard 脚本：路由表 ↔ 代码路由，两向比对 |
| 新组件登记核对 | docs-guard：详设组件清单 ↔ 组件目录 |
| 契约一致性 | manifest 生成 + 本地门禁 diff（前端类型不许与契约漂移） |
| 关键路径 E2E | Playwright / Cypress，进门禁链 |
| 门禁链 | Lint → TypeCheck → Test → **E2E** → Build → Dev 实看（先杀旧进程再启动） |

**原则同全局**：机检能拦的沉本地门禁，文档只留机检不了的（架构判断、视觉合理性、评审要求）。

## 7. 生成项目版前端规范（四步，扩 README §3.7）

> 目标产物是**项目自己的**前端条款，不是前端大全。基线与本文是模板，按项目栈裁剪后落进 `.agents/rules/frontend.md`。

**第一步 · 按栈裁剪**：读 `前端工程化.md` 选型表确定框架 / 状态方案 / 样式方案 / UI 组件库 / 测试与 E2E 工具。删掉项目用不到的：纯后端项目删全部前端节；无主题切换 → 删 §2.3 主题格与 §4 主题条款；无响应式 → 删视口格；无 Tailwind → 删 `@apply` 条款；不用的框架 token 映射表行删掉。**分级表同理**——没有列表/报表的纯表单项目可删「查·新列表」行，没有导出功能的删「查·导出」行，但**「查·查询口径」与「查」的红线不得删**（只要还有列表就要判级）。

**第二步 · 按架构补充**：从 `前端工程化.md` + `docs/05-页面/页面设计.md` + `详设分册` + `.agents/designs/DESIGN.md` 提炼成可判定规则，每条注明权威来源（`docs/… §x`）：
- 目录与别名约定、组件分层与依赖方向（容器 / 业务组件 / shared 边界）；
- 状态方案与状态归属规则、服务端数据获取方式（hook / query 层 / store）；
- 请求与错误处理落点（拦截器位置、信封解析、错误码 → 呈现的映射位置）；
- 四态要求与空态语义区分；
- UI 框架 token 落位（映射还是自建三层键，写死）；
- 硬阻断呈现口径（错误码原文 + 可操作文案，引用详设不复制）。

**第三步 · 落红线与正文**：
- 红线 ≤5 条进 `frontend/AGENTS.md`，其中必须含「影响用户所见的改动必须实看并留四项证据（MCP 优先）」；
- 正文进 `.agents/rules/frontend.md`，骨架用 `templates/FRONTEND-RULES.md`，frontmatter 声明 `description` + `globs`；
- 视觉相关内容只**引用** `DESIGN.md`，不复制 token 值。

**第四步 · 落本地门禁并反证**：把可机检项写成 lint / docs-guard / E2E；然后**用 MCP/内置浏览器实看一遍典型页面**，确认规范描述与实际渲染不矛盾（例如规范说「空态必须有可操作动作」，页面上确实有）——**规范与现实矛盾时以现实为准，先改规范或改代码，别留着假规范**。

**生成时机**：从零项目——`页面设计.md` 与 `DESIGN.md` 定稿后、写第一行业务组件前；接手项目——盘点完成后（尊重现有写法，差异标注「现状 / 目标 / 收敛方式」，棘轮渐进，不一刀切重构）。

## 8. 维护与冲突处理

| 情形 | 处理 |
|---|---|
| 规范与实际代码冲突 | 以代码为准回填规则；大差异走 ADR + 棘轮，**禁**为过门禁批量 `eslint-disable` |
| 每次版本 bump 复核 | UI 框架版本、token 体系、门禁命令、视口与主题口径是否仍准确 |
| 想新增一条「必须遵守」 | 先问能不能写成 lint / docs-guard / E2E；能 → 沉本地门禁，AGENTS 只留一行提醒 |
| 想新增视觉约定 | 落 `DESIGN.md`（token 唯一权威），不是落 rules |
| 实看发现文档与代码不一致 | 以代码为准回填文档并留「回填：原 X 现 Y」；涉及安全红线或硬阻断口径的**停下讨论**，不私改 |
