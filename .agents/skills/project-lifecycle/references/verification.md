# 验证与证据（verification）

完成不是"我觉得好了"，而是可复现的证据。本文件定义门禁、证据格式、失败处理与汇报口径。

## 1. 门禁目录

按仓库实际选择；不确定就跑 CI 用的同一套命令。

| 门禁 | 目的 | 典型命令（按技术栈替换） |
|---|---|---|
| 格式/静态检查 | 风格与明显错误 | `format --check`、`lint` |
| 类型检查 | 类型契约 | `tsc --noEmit`、`mypy`、`cargo check` |
| 构建 | 可编译/可打包 | `build`、`make` |
| 单元测试 | 逻辑契约 | `test`、`pytest`、`go test ./...` |
| 集成/契约测试 | 模块间与外部契约 | `test:integration`、契约测试 |
| 端到端 | 用户路径 | `e2e`、浏览器/API 脚本 |
| 安全 | 依赖与密钥 | 审计命令、secret scan |
| 性能 | 关键路径回归 | 基准脚本、Lighthouse |
| 文档 | 命令可跑、链接有效 | doctest、链接检查、手工冒烟 |

最少：构建 + 相关测试 + lint/类型检查（若仓库有）。没有测试框架时，用最小冒烟脚本或手工清单替代，并记录。

## 2. 基线与复跑

- 改动前跑一次最快门禁，记录已有失败（基线）。
- 最后一次改动**之后**再跑；中间任何代码/配置/依赖变化都使之前的证据失效。
- 报告"新增失败"与"既有失败"分开；不把既有失败算作本次成果，也不趁机修无关问题。
- 命令、工作目录、环境（本地/CI、版本）一起记录，保证可复现。

## 3. 证据格式

每条 AC 的证据至少包含：命令或步骤、结果、关键输出、时间/环境。

```text
AC2：重复提交同一订单只创建一次
命令：npm test -- orders.idempotency
结果：exit 0（3 passed）
关键输出：✓ rejects duplicate submit ✓ returns same order id
时间：2026-11-11 22:40  环境：本地 Node 26 / 提交 abc1234
```

UI 类：截图/录屏 + 操作步骤 + 关键 DOM/控制台/网络摘要。
性能类：改动前后同一场景的数字与测量方法。
数据迁移：dry-run 输出、前后行数/校验和、回滚演练结果。

## 4. 完成定义（DoD）

- [ ] 每条 AC 有证据，或明确标注"未覆盖 + 原因"
- [ ] 最后一次改动后复跑相关门禁，全绿
- [ ] 新增/修改测试有红→绿过程，或说明为何不可自动化
- [ ] flaky 测试重复运行确认，记录处理方式
- [ ] diff 自审：无调试代码、密钥、越界文件、意外生成物
- [ ] 文档/changelog/ADR/状态已更新
- [ ] 风险改动有回滚步骤
- [ ] 未验证项与已知限制已列出

**diff 自审要点**：

- **正确性**：边界、空值、错误路径、并发/幂等、资源释放。
- **契约**：接口/数据/配置兼容；迁移与弃用是否处理。
- **测试**：覆盖 AC 与回归；没有跳过、弱化或盲目更新快照。
- **安全**：输入校验、权限、密钥、日志中的敏感信息。
- **性能**：N+1、无界循环、大对象/大文件、重复计算。
- **可维护性**：命名、重复、死代码、调试残留、注释与行为一致。
- **范围**：只含本任务相关文件；格式化噪音已排除。

## 5. 失败处理

| 情况 | 判定 | 动作 |
|---|---|---|
| 本次改动引入的失败 | 回归 | 修到绿，或回滚；不带病交付 |
| 改动前已存在 | 基线问题 | 记录并报告；除非阻塞 AC，否则不扩大范围 |
| 时好时坏 | flaky | 连续重跑确认；定位不确定性；必要时隔离并登记 |
| 环境/依赖缺失 | 环境问题 | 记录缺失项与影响；不要用"环境问题"掩盖代码问题 |
| 测试本身错误 | 测试缺陷 | 修测试并说明；不得为通过而弱化断言 |
| 无法运行 | 阻塞 | 说明原因、已尝试方案、替代验证方式；降低置信度而不是降低标准 |

禁止：删除/跳过测试、改断言迁就实现、盲目更新快照、只跑一个用例就宣称全绿、用旧输出冒充新证据。

## 6. 安全与破坏性操作检查

在删除、覆盖、迁移、部署、改权限之前：

- [ ] 明确目标路径/环境/账号，确认不是生产或已备份
- [ ] 有回滚步骤并至少演练一次（或 dry-run）
- [ ] 影响面与通知对象清楚
- [ ] 密钥/个人数据不进入日志、提交或截图
- [ ] 不绕过鉴权、TLS、审计与审批

## 7. 汇报口径

最终汇报固定包含：

1. **结果**：完成了什么，AC 状态。
2. **证据**：命令/步骤 + 退出码 + 关键输出。
3. **变更面**：文件/接口/数据/配置。
4. **风险与未验证项**。
5. **下一步**（如未完成）。

措辞对照：

- 已验证 → "已运行 X，exit 0，输出 …"
- 未验证 → "未运行 X，因为 …；建议用 Y 验证"
- 部分完成 → "AC1/AC2 完成并有证据；AC3 未开始"
- 阻塞 → "卡在 X；已尝试 A/B；需要 Y 才能继续"

不说"应该没问题""理论上通过""之前是绿的"。
