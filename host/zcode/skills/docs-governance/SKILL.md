# Steward · 文档治理（ZCode）

> **与主技能「文档流水线」节的分工**：主技能管七阶段流水线怎么**建树**（PRD/FRD/架构/契约/页面/测试/治理与模板索引，模板库在 `references/doc-pipeline/`）；本技能管树建起来之后**怎么别长成屎山**——拆分、归档、版本、读契约、门禁。两者叠加使用，本技能是增量层，不替换主技能的文档流水线。
> **宿主边界**：本技能正文是 ZCode 侧实现。DSH / MiniMax 侧与通用 harness 技能各自单独实现（语义对齐、措辞可异）；不要为了「统一」去改 `shared/`、`host/dsh/`、`dsh/`、`host/minimax/`——ZCode 构建器不消费它们，各宿主技能正文互相独立。
> **不动七阶段编号**：本技能不给 docs 加第八个阶段目录，只给 `07-治理/` 加内部分层、给各基线域加 `history/` 快照区。

## 0. 三句话总纲

1. **活文档管体积，记录文档管索引，基线文档管版本**——三类文档三种待遇；用一套规则管三类，必然崩。
2. **必读是设计出来的，不是喊出来的**：R0 恒读靠体积预算保证读得起；R1 条件必读靠计划字段与派单点名；R2 按需靠索引完备。
3. **能机检的别写进散文**：体积、索引、版本一致性、快照不可变一律交给 `docs-gate`；文档里只写机检不了的判断。

## 1. 三类文档，三种待遇

| 类 | 例子 | 生长方式 | 治理手段 |
|---|---|---|---|
| **活文档** | 根/子 AGENTS、README、docs/README、T1 六件、架构总纲、契约、页面设计、测试方案、执行步骤、开发顺序、评审状态 | 原地修订，同一主题只一份 | 体积预算 + hub-and-spoke 拆册 |
| **记录文档** | ADR 单条、评审记录单篇、postmortem、CHANGELOG 条目 | 只增不改，单条不可变 | 薄索引 + 归档轮转 |
| **基线文档** | PRD、FRD、API 契约、数据模型、DESIGN 冻结节、测试方案（有冻结语义者） | 原地修订 + 里程碑快照 | frontmatter `version` + 修订记录 + `history/` 快照 |

判不准就按更严一类处理：能快照就快照，能拆就拆。

## 2. 活文档体积预算

| 文档 | 预算（行） | 超限动作 |
|---|---|---|
| 根 / 子目录 `AGENTS.md` | 100 | 正文拆 `.agents/rules/`（规范）或 `docs/`（业务）；AGENTS 只留 ≤1 行指针 |
| 根 `README.md` | 120 | 固定四节：定位 / 快速开始 / 当前状态 / 链接；其余一律链接出去 |
| `docs/README.md` | 150 | 目录级索引 + 自动索引区块，不手写逐条记录 |
| T1 `docs/project/*.md` 每件 | 120 | 只留摘要 + 链接，正文进 T3 |
| T3 活文档单册 | 400 | hub-and-spoke 拆册（§3） |
| hub / 索引册 | 150 | 只放跨域公共口径 + 分册目录表 |

- 覆盖：项目根 `steward.config.json` 的 `docsGovernance.budgets`（`validate-config.mjs` 对未知字段只告警，不影响其它门禁）。
- 存量项目：`node <插件>/scripts/docs-gov/docs-gate.mjs <root> --baseline-write` 记录现状，之后只减不增；新项目直接按预算判 error。

## 3. hub-and-spoke 拆册

```
docs/03-契约/
├── API契约.md          # hub：基础约定 + 错误码号段 + 分册目录表（≤150 行，恒读）
├── API-订单.md         # 分册：一个业务域一册（≤400 行）
├── API-审批.md
└── API-事件协议.md
```

规则：

1. **按主题/业务域拆，不按时间拆**；严禁 `XX-v2.md`、`XX-新版.md`（版本写 frontmatter 与头部，见 §7）。
2. hub 保留：跨域公共口径 + 分册目录表（每行：分册｜覆盖范围｜状态）；分册头部回指 hub。
3. 拆册触发：超预算，或单文件覆盖 ≥3 个可独立变更的主题。
4. 拆册动作（复用接手 SOP）：出映射表 → 建分册 → 移动正文 → hub 补目录表 → 全局搜旧引用改指向 → `docs/README.md` 与根 AGENTS 索引同步 → `docs-gate check`。
5. 引用一律写 `文件.md §节`，不复制正文。

## 4. frontmatter 读契约

所有 T3 文档与 `.agents/rules/*.md` 头部加：

```yaml
---
read: always | dir | task | on-demand
scope: backend/**          # read: dir 时必填（生效目录）
budget: 400                # 可选，覆盖默认行数预算
status: active | archived  # 归档/快照必须 archived
version: v2.1              # 基线文档必填，形如 vX.Y 或 X.Y
baseline: true             # 基线文档标记（有冻结语义者）
superseded-by: ../PRD-xxx.md   # 仅历史快照
---
```

| `read` | 含义 | 谁能读 |
|---|---|---|
| `always` | 恒读（R0） | 每轮；**只给** T1 薄记忆与根 AGENTS 摘要，不许放长文 |
| `dir` | 进目录即读 | 在该 `scope` 目录下工作时 |
| `task` | 任务命中才读 | 任务索引表/计划 `docsRead` 点名时 |
| `on-demand` | 按需检索 | 索引定位后片段读 |

硬规则：

- **`AGENTS.md` 一律不加 frontmatter**（宿主原样注入，必须是纯 markdown）；它的读契约由 §5 的索引表承载。
- 机检：`read` 枚举、`dir` 必带 `scope`、`archived` 必须在 `history/` 或 `archive/`、`superseded-by` 指向存在文件——全在 `docs-gate` G2/G8。

## 5. 三级读契约与派单

| 级 | 内容 | 触发 | 保障 |
|---|---|---|---|
| **R0 恒读** | 根 `AGENTS.md` + `CONSTITUTION.md` + T1 薄记忆 | 每轮 | 体积预算（读得起才谈必读） |
| **R1 条件必读** | 进目录→该层 AGENTS + 对应 `.agents/rules/`；改契约→对应分册；任务命中→索引表指定文档 | 目录 / 任务 | AGENTS「改什么→必读什么」表；**计划字段 `docsRead`**；派单点名；终审核查 |
| **R2 按需** | 其余全部 | agent 自行索引定位 | hub / 目录 README 完备 + 死链检查 |

**排计划的硬要求**：T3 项目（或任何跨模块任务）写 `03-plan.json` 时，每个任务必须带 `docsRead: ["<必读文档路径>", ...]`：

- 路径必须真实存在（`docs-gate` G11 校验）；
- `docTier=3` 时不得为空；
- 派单 prompt 必须原样带上该任务的 `docsRead`，并写一句「先读这些文档再动手」；
- 终审（reviewer）核对：改动涉及的口径是否都在 `docsRead` 覆盖范围内，交付报告「对齐文档」声明是否与之一致。

**读长文协议（写进 AGENTS 工作流）**：

1. 先读 hub / 索引，再 `grep`（或等价检索）定位节，最后按 `offset/limit` 片段读——**禁止整文件倾倒**。
2. 实现任务**禁读** `history/` 快照与 `archive/`（历史基线不是现行口径）；只有溯源/审计任务可读，且结论必须回指现版。
3. 回复开头保留「对齐文档：<文件> §<节>」一行。

## 6. `07-治理/` 内部分层与归档轮转

```
docs/07-治理/
├── 执行步骤.md            # 活文档：进度 SSOT（剩余工序、开放项台账）
├── 开发顺序.md            # 活文档：开工 SSOT（波次/并行/估算）
├── 评审状态.md            # 活文档：各阶段最新门禁结论「一页通」
├── ADR-索引.md            # 活索引：每条一行
├── adr/
│   ├── ADR-0001-<标题>.md  # 一号一文件，单条不可变
│   └── ADR-0002-<标题>.md
└── 评审记录/
    ├── README.md           # 活索引：近期逐条 + 归档链接
    ├── 评审记录-YYYYMMDD-<主题>.md
    └── archive/2026Q3/     # 按季归档（目录级索引：只在 README 留一行归档链接）
```

规则：

1. **`07-治理/` 根只放活文档**（上述四件）；任何 `评审记录-*.md` 落在根都算违规（`docs-gate` G4）。
2. **`评审状态.md` 是新增的「一页通」**，解决「想看现状得翻历史垃圾堆」：每阶段一行，写最新门禁结论 + 链接，不复制正文。

```markdown
# 评审状态（各阶段最新门禁结论）
> 只记一行结论 + 证据链接；正文进对应评审记录，不在此复制。

| 阶段 | 最新结论 | 日期 | 评审记录 |
|---|---|---|---|
| ① 需求 | 可进入架构 | 2026-11-10 | [评审记录-20261110](评审记录/评审记录-20261110-需求基线.md) |
| ③ 契约 | 修复后可 | 2026-11-12 | [评审记录-20261112](评审记录/评审记录-20261112-契约冻结.md) |
```

3. **归档轮转**：每季度把已闭项的评审记录移入 `评审记录/archive/YYYYQn/`；移动后 `docs-gate fix` 重写索引区块，`doc-check` 保持绿。
4. **边界（最容易错的一条）**：**run 级报告不进 docs**——QA 报告、终审报告、浏览器证据留在 `tmp/steward/<run>/reports/`（T2 工件）；只有**阶段门禁评审**才写 `docs/07-治理/评审记录/`。别把所有评审都往 07 倒。
5. 索引为什么必须逐文件：`doc-check.mjs` 对 `docs/01..07` 递归逐文件校验索引（有 E-UNINDEXED），归档文件也逃不掉。所以用 **自动索引区块**（`<!-- docs-gate:index:begin -->`）由脚本维护，人不手写。

## 7. 记录文档三铁律与 ADR

1. **单条不可变**：一条评审/一个决策一份（或总集内一节），历史正文不改；修订=补记或新条取代旧条（旧条标「已被 ADR-00XX 取代」）。
2. **薄索引恒在**：每条一行（编号｜日期｜主题｜结论/状态｜链接）。agent 恒读索引，按需点开单条。
3. **归档分层**：按季轮转进 `archive/`，活索引只留近期 + 归档链接。

**ADR 细则**：`adr/ADR-000X-<标题>.md` 一号一文件，头部 `> 状态：提议|接受|拒绝|已落地|已废弃`、`> 日期`、`> 决策者`；正文五节：背景 / 决策 / 备选方案 / 后果 / 参考。`ADR-索引.md` 每条一行，状态与文件头一致（G6 双向核对）。T1 `DECISIONS.md` 只保留**现行有效**决策摘要（≤1 屏），被取代的移出并指向索引归档段。

## 8. 版本快照与溯源

### 8.1 模型：现版原地改，基线冻结才快照

```
docs/01-需求/
├── PRD-xxx.md               # 现版 v2.1：路径永远稳定，SSOT，原地修订
├── FRD-xxx.md
└── history/                 # 快照区（不可变）
    ├── README.md            # 版本索引：版本｜日期｜摘要｜依据｜快照
    ├── manifest.json        # sha256 清单（不可变性机检）
    └── PRD-xxx-v2.0.md      # 旧基线，头部「已被 v2.1 取代 → 现版链接」
```

| 决策 | 取法 | 理由 |
|---|---|---|
| 现版路径 | 永远不带版本号 | 保住「同一主题只一份」与全部既有链接 |
| 快照时机 | **仅基线冻结**（范围/AC/契约口径等 major 变化）；澄清/笔误/补充说明不拍 | 细粒度历史 git 免费管，快照只管语义里程碑 |
| 快照性质 | 不可变 + 目录级索引 | 是留痕不是第二事实源 |
| 与 git 分工 | git=逐提交；快照=不装 git 也能读的里程碑 | 交接/导出/审计不断链 |

### 8.2 修订记录表（现版尾部；超预算再拆独立文件）

```markdown
## 修订记录
| 版本 | 日期 | 变更摘要（FR/FP 编号） | 依据（拍板留痕） | 拍板人 | 快照 |
|---|---|---|---|---|---|
| v2.1 | 2026-11-12 | FR-3.2 审批阈值 100→500；新增 FR-7 | ADR-0012 + 评审记录-20261110 | 用户 | [v2.0](history/PRD-xxx-v2.0.md) |
```

铁律：

1. **FR/FP/错误码编号永不复用、永不重排**；废弃标 `deprecated@v2.1`。编号是跨版本溯源主键。
2. **依据三选一必填**（ADR / 评审记录 / `01-approval.md`）——与变更入口「不拍板不动文档」对齐；修订行就是变更入口的落档终点。
3. **关键引用可钉版本**：`PRD.md §FR-3.2（v2.0 基线）`。现版改口径时，钉版本引用立刻暴露「需重算」，而不是静默漂移。

### 8.3 双向溯源

- **正向**（口径何时/为何变）：现版修订表检索 FR 编号 → 修订行 → 依据链接看拍板过程 → 快照看旧基线原文。
- **反向**（某个交付时点的基线）：`05-record.md` 记当次对齐的文档版本 → `history/README.md` 按版本/日期定位快照。
- **联动**：`05-record.md` 的「文档更新清单」加一列「版本 bump（vX.Y→vX.Z）」，run 工件与文档版本互锚。

### 8.4 快照 SOP

```bash
# 一条命令：旧基线进 history/ + manifest + 索引 + superseded-by，现版 bump + 修订行
node <插件>/scripts/docs-gov/doc-snapshot.mjs docs/01-需求/PRD-xxx.md --next v2.1 \
  --note "FR-3.2 阈值 100→500；新增 FR-7" --ref "ADR-0012 + 评审记录-20261110" --by 用户
node <插件>/scripts/docs-gov/docs-gate.mjs . check
```

顺序不可省：**先快照再改口径**（快照存的是旧基线）；幂等，重复执行输出 `skip`。快照文件**禁止手改**——`manifest.json` 哈希会立刻报 G8。

## 9. 本地门禁（ZCode 侧脚本）

两个脚本随插件包提供（`<插件>/scripts/docs-gov/`），纯 Node 零依赖，在目标仓库根用绝对路径运行。

| 脚本 | 作用 | 何时跑 |
|---|---|---|
| `docs-gate.mjs <root> check` | G1–G11：体积预算、frontmatter、AGENTS 无 frontmatter、07 分层、索引区块、ADR 双向、版本三处一致、快照完整性、现版不入历史、修订依据、计划 `docsRead` | 每次交付收尾、评审前、维护循环 |
| `docs-gate.mjs <root> init` | 建 07 内部分层 + 各域 `history/` + 索引骨架（幂等不覆盖） | 新建 T3 项目 / 首次启用治理 |
| `docs-gate.mjs <root> fix` | 重写自动索引区块、补齐 manifest 缺项 | 归档轮转后、`G5` 报错时 |
| `docs-gate.mjs <root> --baseline-write` | 存量项目记基线（体积超限与缺依据先记账，只减不增） | 接手存量项目时 |
| `doc-snapshot.mjs <doc> --next <ver> ...` | 基线快照（§8.4） | 口径 major 变更、交付冻结 |

要点：

- 与 `doc-check.mjs` **并存不互替**：`doc-check` 管树/死链/T1/索引基线；`docs-gate` 管治理增量。两者都要绿，顺序无依赖。
- 退出码非 0 一律如实上报，不许解释掉。
- 归档文件必须进自动索引区块（见 §6.5），否则 `doc-check` 的 E-UNINDEXED 会红——这是最常见的踩坑点。

## 10. 治理归属：不设专职文档工程师

| 职责 | 归谁 | 保障 |
|---|---|---|
| **编写**（谁决策谁写） | pm / architect / dev，不变 | 模板 + frontmatter + 联动表 |
| **质量评审**（第二双眼睛） | reviewer，不变 | 阶段门禁评审 + 对齐文档/`docsRead` 核查 |
| **治理**（结构/索引/归档/预算/一致性） | Lead 收尾 + 维护循环 + 机器门禁 | `docs-gate` 机检 + `05-record` 文档更新清单 |

理由：文档即决策本身（PRD 由 pm 在澄清中写、契约由 architect 在设计时写，先于代码）；专职写手二手转写会让 SSOT 变传话游戏，且「谁改代码同批改文档」的原子性被交接破坏——正是要消灭的漂移。痛点是结构性的，该修的是预算/索引/归档/门禁，不是加人头。

落法（都不新增角色）：

- **每轮收尾**：Lead 在收尾阶段跑一次 `docs-gate check`，把文档更新与版本 bump 记进 `05-record.md`。
- **周期性**：维护循环新增「文档治理」任务类——归档轮转、补快照、索引重建、预算 burn-down；作为维护任务派给一个 dev 实例或 inline，**不是常驻角色**。
- **一次性建树/大迁移**：用现有角色 + 文档专项任务书派单（architect 管结构、dev 管机械搬运），角色系统支持同角色多实例。
- 真值得设专职的边界：超大合规 T3、数百份文档、文档量确实卡交付；或对外技术写作（用户手册/API 门户）。即便如此也优先任务级派单，而非常驻名册。

## 11. 反模式

| 反模式 | 症状 | 正解 |
|---|---|---|
| 三类文档一套规则 | 记录越堆越长、活文档没人拆 | §1 分治 |
| AGENTS 塞长正文 | 每轮注入开销爆炸、模型忽略红线 | 正文拆 `.agents/rules/`，AGENTS 留 ≤1 行指针 |
| `XX-v2.md` / 按时间拆册 | 多份"现版"互相打架 | 现版路径稳定 + `history/` 快照（§8） |
| 快照手改 | 哈希不符、审计失真 | 禁止手改；重做走人工确认 |
| 把 `history/` 当现行口径 | 实现按旧基线漂移 | 实现任务禁读；快照头 `superseded-by` 弹回现版 |
| 所有评审都往 07 倒 | 07 变垃圾场、索引膨胀 | 只有阶段门禁评审进 docs；run 报告留 T2 |
| 归档后忘了索引 | `doc-check` E-UNINDEXED 红 | `docs-gate fix` 重写自动区块 |
| 为了绿删/弱化检查 | 门禁失效 | 记基线只减不增（ratchet），不删检查 |
| 修订行不挂依据 | 溯源断链、AI 私改无法追责 | 依据三选一必填（G10） |
| 编号重排/复用 | 跨版本溯源错位 | 编号唯一永久，废弃标记不复用 |

## 12. 项目侧落地清单

**新项目**：`docs-gate <root> init` → 补 `steward.config.json` 的 `docsGovernance` → 按主技能「文档流水线」建七阶段树 → 每份文档加 frontmatter → `docs-gate check` 绿 → 进实现。

**接手存量**：先按接手 SOP 盘点映射 → 存量记基线（`--baseline-write`）→ 07 分层改造（`init` + 移文件）→ `fix` 重建索引 → `docs-gate check` 绿（允许基线内超限）→ 逐批 burn-down。

**每次交付收尾**：`docs-gate check` → 修订表/评审状态更新 → `05-record` 记版本 bump 与文档更新清单 → 入库。
